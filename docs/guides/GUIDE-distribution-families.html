glissando · new distribution families (Box-Cox)

Implements DIST-1 — the Box-Cox power family BCCG (Cole-Green), BCT (Box-Cox-t), BCPE (power exponential): the distributions GAMLSS is known for and #4 on the stack-rank. It is written as a worked example of the whole Distribution trait, so it doubles as the template for every later family (DIST-2/DIST-3/DIST-4/DIST-5).

Why these first: BCCG models a skew positive response by Box-Cox-transforming it to a standard normal, parameterized by median μ, coefficient-of-variation σ, and skewness ν. It is the engine behind LMS centile curves (growth charts) — the canonical GAMLSS deliverable that INFER-2 centiles already exist to consume.

The trait checklist

A family is a struct implementing Distribution (src/distributions/mod.rs:32). Below is every method, with the BCCG answer. student_t.rs is the closest existing template — 3 parameters (μ/σ/ν), robust seeds — so copy its file shape.

parameters()["mu","sigma","nu"].
default_link()μ → log (μ is a positive median), σ → log, ν → identity. (BCT/BCPE add a 4th positive param τ → log.)
derivatives()Score u + Fisher w per parameter, on the η scale. The math core — see below.
loglik_pointwise()Per-row log-density. Drives the default pdf (mod.rs:96) for free.
cdf() / quantile()Required (mod.rs:104–120). For BCCG both reduce to the normal Φ / Φ⁻¹ of the Box-Cox z-score (below).
variance() / expected_value()variance for Pearson residuals; expected_value defaults to μ (mod.rs:69) — override since the BCCG mean ≠ median.
name()"BCCG" — used in errors and the from_name factory.
initial_value()Robust seeds (mod.rs:128): μ₀ = median(y), σ₀ from a robust CV, ν₀ = 1 (start at the lognormal-ish identity). Mirrors StudentT's median/MAD seeding.
is_discrete()Stays false (continuous, y > 0).

The Box-Cox z-score (shared spine)

All three families share one transform from y > 0 to a standardized residual z; they differ only in the distribution z follows.

z = ((y/μ)^ν − 1) / (ν·σ)     if ν ≠ 0
z = log(y/μ) / σ              if ν = 0   (limit)

The log-density is the density of z plus the Jacobian d z/d y:

log f(y) = log h(z) + (ν−1)·log(y) − ν·log(μ) − log(σ)
  • BCCG: h = standard normal ⇒ log h(z) = −½z² − ½log(2π). (gamlss truncates the lower tail at y=0; renormalize by Φ(1/(σ|ν|)) for exactness, or note the approximation.)
  • BCT: z ~ t_τ (Student-t with τ df) ⇒ adds the heavy-tail parameter τ; reuse the t-density already in student_t.rs.
  • BCPE: z ~ power-exponential(τ) ⇒ adds a kurtosis parameter; needs the PE normalizing constant (gamma functions — src/math.rs has lgamma).

cdf(y) = Φ(z) (BCCG) and quantile(p) = μ·(1 + ν·σ·Φ⁻¹(p))^(1/ν) — invert the z-score. The full derivative forms (∂z/∂μ, ∂z/∂σ, ∂z/∂ν and the resulting score/Fisher) belong in docs/math/mathematics.md §1 alongside the existing per-distribution derivations; digamma/trigamma for BCT/BCPE are in §2 / src/math.rs.

Build order

  1. New file src/distributions/bccg.rs. Copy the shape of student_t.rs (μ/σ/ν struct, Default, the trait impl skeleton). Register the module in src/distributions/mod.rs.
  2. Transform + likelihood first. Implement the z-score helper, loglik_pointwise, cdf, quantile. These are independently testable before any derivative work and unblock pdf (default) and centiles.
  3. Derivatives (the heavy step). Implement derivatives returning score/Fisher for μ, σ, ν on the η scale. Validate against a finite-difference of loglik_pointwise before trusting it — a wrong score silently degrades fits rather than erroring.
  4. Register in the factory. Add "BCCG" to the by-name distribution lookup that the trait-object factory uses (the same match that lists the existing 8 families), so native + JSON + WASM + Python can all instantiate it. Grep for an existing name like "StudentT" to find every arm.
  5. Repeat for BCT then BCPE. Same file-template; only h(z), the extra parameter, and its derivative column change. Note in each file where it diverges from BCCG so the next family author sees the seam.

Tests & reference oracle

Oracle: R gamlss BCCG() / BCT() / BCPE() — the like-for-like Rigby-Stasinopoulos oracle with the same μ/σ/ν(/τ) parameterization. This matters: per the project's StudentT experience, compare against the matching gamlss family, not mgcv (mgcv has no Box-Cox analog). Use gamlss's dBCCG/pBCCG/qBCCG for the distributional functions and a fitted gamlss(y~..., family=BCCG) for coefficients.

  • Coefficient recovery (tests/correctness.rs style): simulate from known μ/σ/ν via qBCCG, fit, assert recovery.
  • Parity (tests/mgcv_reference.rs style, #[ignore]): fixtures from benchmark/run_comparison.sh (add a BCCG case to fit_gamlss.R); compare coefficients + fitted centiles.
  • Distributional round-trips: cdf(quantile(p)) ≈ p; pdf integrates to ≈1 over a fine grid; finite-difference of loglik_pointwise matches derivatives at random (μ,σ,ν).

Cross-surface bindings BIND-3

Surface the family exactly as the existing 8 are surfaced: a name in the JSON facade (src/json.rs), a constructor in the WASM distribution enum (src/wasm.rs), and a Python distribution class (src/python.rs). Because all of μ/σ/ν are fitted (not structural like Binomial n or Ocat k), SER-1 does not bite — BCCG round-trips through to_json/from_json by name with no stateful-distribution work. Add a centile worked example (DOC-3) since the LMS growth-chart use case is the marquee demo.
