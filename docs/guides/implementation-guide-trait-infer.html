glissando · implementation guide

The four critical-path roadmap items that make glissando "GAMLSS-shaped" — TRAIT-1, INFER-1, INFER-2, TRAIT-2 — with the math derived and the code sketched against the current source. IDs cross-reference docs/ROADMAP.html.

The items form two independent chains:

TRAIT-1  (cdf / pdf / quantile on Distribution)
   ├──► INFER-1  (randomized quantile residuals)
   └──► INFER-2  (centiles / quantile prediction / predictAll)

TRAIT-2  (mu_eta on Link)  — independent; unblocks the LINK-* expansion

Recommended order: TRAIT-1 first, then INFER-1 and INFER-2 in parallel once the trait lands. TRAIT-2 is independent and touches only links.rs.

Notation

A GAMLSS models a response Y with density (or mass) f(y | θ) whose up to four parameters θ = (μ, σ, ν, τ) each have their own additive predictor. For parameter θ_k:

η_k = X_k β_k = Σj skj(x)   (linear predictor)     θ_k = g_k−1(η_k)   (response scale, via the link g_k)

In code, the response-scale parameter vectors arrive as params: &HashMap<&str, &Array1<f64>> keyed by name ("mu", …); a row i is one observation's θ_i. The existing trait already exposes the log-density loglik_pointwise = log f(y_i | θ_i), the score/Fisher pairs derivatives, and the marginal moments variance / expected_value. TRAIT-1 adds the distributional trio — cdf, pdf, quantile — that everything statistically distinctive about GAMLSS needs.

Two rules hold throughout:

  • Adding a required method to a public trait (Distribution, Link) is a breaking change for external implementors. Where an honest fallback exists, give the method a default body; where none does (cdf/quantile), make it required and accept the major bump.
  • When a public, WASM-exposed type or method changes, regenerate pkg/ (wasm-pack build --no-default-features --features wasm) — the committed npm artifact (BIND-1).

TRAIT-1 — cdf / pdf / quantile on the Distribution trait

Files: src/distributions/mod.rs (trait) · one method block per family in src/distributions/{gaussian,gamma,poisson,negative_binomial,beta,student_t,binomial,ocat}.rs.

Mathematical background

The cumulative distribution and its inverse are

F(y | θ) = P(Y ≤ y | θ) = ∫−∞y f(t | θ) dt   (continuous)     F(y | θ) = Σt ≤ y f(t | θ)   (discrete) Q(p | θ) = F−1(p | θ) = inf { y : F(y | θ) ≥ p },   p ∈ (0, 1)

Every family glissando ships has a CDF expressible through one of three special functions, all in statrs 0.18 (already a dependency — six families use its ln_gamma today):

erf(x) = (2/√π) ∫0x e−t² dt  →  Normal, and Φ−1 for INFER-1 P(a, x) = γ(a, x) / Γ(a) (lower reg. incomplete gamma)  →  Gamma, Poisson Ix(a, b) = B(x; a, b) / B(a, b) (reg. incomplete beta)  →  Beta, NegBin, Binomial
  • statrs::function::erf::{erf, erf_inv}
  • statrs::function::gamma::{gamma_lr /* P(a,x) */, gamma_ur /* Q(a,x)=1−P */}
  • statrs::function::beta::beta_reg /* I_x(a,b) */
  • or the higher-level statrs::distribution::{Normal, Gamma, Beta, StudentsT, …} implementing ContinuousCDF / DiscreteCDF with .cdf() and .inverse_cdf() — construct one per row (params differ per observation) and map.

The subtlety is that glissando uses the gamlss (mean/dispersion) parameterization, which must be mapped to each special function's standard arguments. The table gives the mapping together with the mean/variance identities so an implementer can verify each conversion independently:

Where the Poisson CDF identity comes from (representative of the discrete cases):

F(m | μ) = Σk=0m e−μ μk/k! = Q(m+1, μ) = Γ(m+1, μ)/Γ(m+1),   m = ⌊y⌋

i.e. the regularized upper incomplete gamma at integer first argument equals the Poisson survival-complement — so gamma_ur(⌊y⌋+1, μ) is the Poisson CDF with no summation loop.

Trait additions

// in `pub trait Distribution`  (src/distributions/mod.rs)

/// Cumulative distribution `F(y_i | θ_i) = P(Y ≤ y_i)`, vectorized over rows.
/// For discrete families this is the right-continuous step CDF, evaluated at ⌊y⌋.
fn cdf(&self, y: &Array1<f64>, params: &HashMap<&str, &Array1<f64>>)
    -> Result<Array1<f64>, GamlssError>;

/// Density (continuous) or mass (discrete) `f(y_i | θ_i)`.
///
/// Default: `exp(loglik_pointwise)`, correct for every family whose
/// `loglik_pointwise` returns a true (normalized) log-density/-mass — all do today.
fn pdf(&self, y: &Array1<f64>, params: &HashMap<&str, &Array1<f64>>)
    -> Result<Array1<f64>, GamlssError> {
    Ok(self.loglik_pointwise(y, params)?.mapv(f64::exp))
}

/// Inverse CDF / quantile: smallest `y` with `F(y) ≥ p_i`, element-wise over `p ∈ (0,1)`.
fn quantile(&self, p: &Array1<f64>, params: &HashMap<&str, &Array1<f64>>)
    -> Result<Array1<f64>, GamlssError>;

/// Whether the response is discrete. Drives the randomized branch in INFER-1
/// (discrete families need `F(y)` *and* `F(y−1)`). Default: continuous.
fn is_discrete(&self) -> bool { false }

pdf gets a default; cdf, quantile, is_discrete are the per-family work, across all 8 families — including the stateful Binomial and Ocat that from_name skips (they implement the trait directly).

Worked implementations

Gaussian — closed form, vectorized with the existing par_zip3_map helper (src/math.rs):

use statrs::function::erf::{erf, erf_inv};
use std::f64::consts::SQRT_2;

fn cdf(&self, y, params) -> Result<Array1<f64>, GamlssError> {
    let mu = require(self, params, "mu")?;
    let sigma = require(self, params, "sigma")?;
    Ok(par_zip3_map(y, mu, sigma, |yi, mui, si| {
        let z = (yi - mui) / si.max(MIN_POSITIVE);
        0.5 * (1.0 + erf(z / SQRT_2))
    }))
}

fn quantile(&self, p, params) -> Result<Array1<f64>, GamlssError> {
    let mu = require(self, params, "mu")?;
    let sigma = require(self, params, "sigma")?;
    Ok(par_zip3_map(p, mu, sigma, |pi, mui, si| {
        let pc = pi.clamp(1e-12, 1.0 - 1e-12);             // keep erf_inv finite
        mui + si * SQRT_2 * erf_inv(2.0 * pc - 1.0)
    }))
}

Gamma — continuous, delegate to the special function (no per-row object needed for the CDF; the quantile borrows statrs' Newton inverse):

use statrs::function::gamma::gamma_lr;
use statrs::distribution::{ContinuousCDF, Gamma as SGamma};

fn cdf(&self, y, params) -> Result<Array1<f64>, GamlssError> {
    let mu = require(self, params, "mu")?;
    let sigma = require(self, params, "sigma")?;
    Ok(par_zip3_map(y, mu, sigma, |yi, mui, si| {
        if yi <= 0.0 { return 0.0; }                       // support is y > 0
        let shape = 1.0 / (si * si);
        let scale = mui * si * si;
        gamma_lr(shape, yi / scale)                        // P(α, y/s)
    }))
}

fn quantile(&self, p, params) -> Result<Array1<f64>, GamlssError> {
    let mu = require(self, params, "mu")?;
    let sigma = require(self, params, "sigma")?;
    Ok(par_zip3_map(p, mu, sigma, |pi, mui, si| {
        let shape = 1.0 / (si * si);
        let rate  = 1.0 / (mui * si * si);                 // statrs Gamma is (shape, rate)
        SGamma::new(shape, rate).expect("valid params").inverse_cdf(pi.clamp(1e-12, 1.0 - 1e-12))
    }))
}

Poisson — discrete: CDF via the upper-incomplete-gamma identity above; quantile by a monotone search on the integer support (a generic helper both discrete families can share):

use statrs::function::gamma::gamma_ur;

fn is_discrete(&self) -> bool { true }

fn cdf(&self, y, params) -> Result<Array1<f64>, GamlssError> {
    let mu = require(self, params, "mu")?;
    Ok(par_zip_map(y, mu, |yi, mui| {
        if yi < 0.0 { return 0.0; }
        let m = yi.floor();
        gamma_ur(m + 1.0, *mui)                            // Q(⌊y⌋+1, μ)
    }))
}

fn quantile(&self, p, params) -> Result<Array1<f64>, GamlssError> {
    let mu = require(self, params, "mu")?;
    Ok(par_zip_map(p, mu, |pi, mui| {
        discrete_quantile(pi.clamp(0.0, 1.0 - 1e-12),
                          |k| gamma_ur(k as f64 + 1.0, *mui))   // CDF as a fn of integer k
    }))
}

// shared helper (src/distributions/mod.rs, pub(crate)) — smallest k with CDF(k) ≥ p.
// Doubling bracket then bisection keeps it O(log k) even for large μ.
pub(crate) fn discrete_quantile(p: f64, cdf_at: impl Fn(u64) -> f64) -> f64 {
    if p <= cdf_at(0) { return 0.0; }
    let (mut lo, mut hi) = (0u64, 1u64);
    while cdf_at(hi) < p { lo = hi; hi = hi.saturating_mul(2); }
    while hi - lo > 1 {
        let mid = lo + (hi - lo) / 2;
        if cdf_at(mid) < p { lo = mid; } else { hi = mid; }
    }
    hi as f64
}

The remaining families follow the table: Student-t via StudentsT::new(0,1,ν) with the z=(y−μ)/σ shift; Beta via beta_reg(a,b,y) and Beta::inverse_cdf; NegBin/Binomial via beta_reg + discrete_quantile; Ocat via a cumulative sum of the existing category_probs.

Right-continuity matters. Keep the discrete CDF evaluated at ⌊y⌋ so that cdf(k) − cdf(k−1) = pdf(k) at integer support points — INFER-1's de-lumping step relies on exactly that identity.

Tests

Add shared checkers next to check_score_via_finite_diff in mod.rs::test_helpers:

/// Continuous round-trip: Q(F(y)) ≈ y.
pub fn check_cdf_quantile_roundtrip<D: Distribution + ?Sized>(
    d: &D, y: &Array1<f64>, owned: &[(&'static str, Array1<f64>)], tol: f64,
) {
    let p = params_view(owned);
    let u = d.cdf(y, &p).unwrap();
    let back = d.quantile(&u, &p).unwrap();
    for i in 0..y.len() {
        assert!((back[i] - y[i]).abs() < tol, "{} obs {}: Q(F(y))={} y={}",
                d.name(), i, back[i], y[i]);
    }
}

/// CDF↔pdf consistency: d/dy F ≈ f (continuous) via central difference.
pub fn check_cdf_matches_pdf<D: Distribution + ?Sized>(/* … */) { /* (F(y+h)−F(y−h))/2h ≈ pdf(y) */ }
  • Round-trip + CDF/pdf consistency for every continuous family; for discrete check cdf(k) − cdf(k−1) ≈ pmf(k).
  • Monotone CDF ∈ [0,1]; monotone quantile on (0,1); tail anchors F(+∞)→1, F(−∞)→0.
  • A proptest over random params asserting CDF monotonicity and the round-trip, matching the proptest style already in gaussian.rs / links.rs.

INFER-1 — Randomized (normalized) quantile residuals

Files: src/fitting/diagnostics.rs (compute fn) + GamlssModel method in src/lib.rs. Depends on TRAIT-1.

Why they are the GAMLSS residual

The construction (Dunn & Smyth, 1996) rests on the probability integral transform: if Y is continuous with CDF F, then

U = F(Y | θ) ∼ Uniform(0, 1) ⟹ r = Φ−1(U) ∼ N(0, 1)

So if the fitted model is correct, the residuals r_i = Φ⁻¹(F(y_i | θ̂_i)) are standard normal regardless of the family — heavy-tailed, skewed, discrete, all map to the same N(0,1) yardstick. That is what makes one Q-Q/worm plot work across every distribution, which Pearson residuals cannot.

For a discrete response F jumps, so F(Y) is not uniform. The randomized PIT repairs this by spreading each atom across the jump interval:

ai = F(yi − 1 | θ̂i),  bi = F(yi | θ̂i),  vi ∼ Uniform(0,1) ui = ai + vi·(bi − ai) ∼ Uniform(0,1),   ri = Φ−1(ui)

Because the draw is stochastic, the API must be explicit and seedable rather than folded into the always-computed ModelDiagnostics.

Code

Reuse the crate's existing RNG convention (rand 0.10: StdRng::seed_from_u64 for seeded, rand::rng() for unseeded — the exact pattern in fitting::sample_posterior_seeded). Φ⁻¹ is the standard-normal quantile; factor it out so the Gaussian family impl and the residual code share one definition:

// src/fitting/diagnostics.rs  (or src/math.rs)
use statrs::function::erf::erf_inv;
use std::f64::consts::SQRT_2;

/// Standard-normal quantile Φ⁻¹(p). Shared by Gaussian::quantile and INFER-1.
pub(crate) fn std_normal_quantile(p: f64) -> f64 {
    SQRT_2 * erf_inv(2.0 * p.clamp(1e-12, 1.0 - 1e-12) - 1.0)
}
// src/fitting/diagnostics.rs
use rand::rngs::StdRng;
use rand::{rng, Rng, SeedableRng};

pub fn quantile_residuals<D: Distribution + ?Sized>(
    family: &D,
    y: &Array1<f64>,
    params: &HashMap<&str, &Array1<f64>>,
    seed: Option<u64>,
) -> Result<Array1<f64>, GamlssError> {
    let u = if family.is_discrete() {
        let hi = family.cdf(y, params)?;                          // F(y)
        let lo = family.cdf(&(y - 1.0), params)?;                 // F(y−1)
        // One generic helper, two rng concretizations — matches sample_posterior_seeded.
        fn fill<R: Rng>(rng: &mut R, lo: &Array1<f64>, hi: &Array1<f64>) -> Array1<f64> {
            ndarray::Zip::from(lo).and(hi)
                .map_collect(|&a, &b| a + (b - a) * rng.random::<f64>())
        }
        match seed {
            Some(s) => fill(&mut StdRng::seed_from_u64(s), &lo, &hi),
            None     => fill(&mut rng(), &lo, &hi),
        }
    } else {
        family.cdf(y, params)?                                    // continuous: u = F(y)
    };
    Ok(u.mapv(std_normal_quantile))                               // r = Φ⁻¹(u), clamped inside
}
// src/lib.rs — on GamlssModel
/// Randomized normalized quantile residuals (gamlss's default residual).
/// `seed` makes the discrete-family randomization reproducible; ignored for
/// continuous families. Use the same response `y` the model was fit on.
pub fn quantile_residuals<D: Distribution + ?Sized>(
    &self, family: &D, y: &Array1<f64>, seed: Option<u64>,
) -> Result<Array1<f64>, GamlssError> {
    // Same fitted-params view diagnostics::compute builds from self.models.
    let params: HashMap<&str, &Array1<f64>> =
        self.models.iter().map(|(k, v)| (k.as_str(), &v.fitted_values)).collect();
    fitting::diagnostics::quantile_residuals(family, y, ¶ms, seed)
}

(fitted_params_view in diagnostics.rs builds exactly this map — expose it pub(crate) and call it instead of re-inlining, if you prefer one source.)

Tests

  • Calibration: simulate from a known Gaussian/Gamma/Poisson fit; residuals have mean ≈ 0, variance ≈ 1, and high Filliben correlation (sorted residuals vs std_normal_quantile of plotting positions — the DIAG-4 statistic).
  • Determinism: same seed ⇒ identical residuals; different seed ⇒ different (discrete only); continuous ignores the seed.
  • Discrete bracketing: every u_i ∈ (F(y_i−1), F(y_i)] before the Φ⁻¹.

INFER-2 — Centiles / quantile prediction / predictAll

Files: new GamlssModel methods in src/lib.rs. Depends on TRAIT-1.

Math

A centile curve at level α is the function of the covariates whose fitted distribution puts mass α below it:

Cα(x) = Q(α | θ̂(x)) such that F(Cα(x) | θ̂(x)) = α

For a Gaussian fit this is the familiar μ̂(x) + σ̂(x)·z_α, but in GAMLSS σ, ν, τ all vary with x, so the centiles fan and bend — capturing changing spread, skew, and kurtosis. That is the signature GAMLSS deliverable (growth charts, reference ranges). Three layered outputs:

  1. predictAll — the full fitted parameter vector θ̂(x) on new data. This already exists as GamlssModel::predict (it returns every parameter, not just μ). Add a documented alias, or leave it and note the equivalence.
  2. Centiles — C_α(x) for a set of levels α; just family.quantile(α, θ̂(x)).
  3. Per-observation quantile prediction — same with a row-varying p vector, for predictive intervals.

Code

// src/lib.rs — on GamlssModel

/// Response-scale centile curves for `new_data`. `percentiles` are in percent
/// (gamlss default: 0.4, 2, 10, 25, 50, 75, 90, 98, 99.6). Returns one column
/// per requested centile, keyed "C<pct>".
pub fn centiles<D: Distribution + ?Sized>(
    &self, new_data: &DataSet, family: &D, percentiles: &[f64],
) -> Result<HashMap<String, Array1<f64>>, GamlssError> {
    let params_owned = self.predict(new_data, family)?;          // θ̂(x): predictAll
    let params: HashMap<&str, &Array1<f64>> =
        params_owned.iter().map(|(k, v)| (k.as_str(), v)).collect();
    let n = new_data.n_obs()
        .ok_or_else(|| GamlssError::Input("new_data has no columns".into()))?;

    let mut out = HashMap::new();
    for &pct in percentiles {
        let p = Array1::from_elem(n, (pct / 100.0).clamp(1e-9, 1.0 - 1e-9));
        out.insert(format!("C{pct}"), family.quantile(&p, ¶ms)?);   // C_α(x)
    }
    Ok(out)
}

/// Per-observation quantile prediction: `p[i]` is the level for row `i`.
pub fn quantile_prediction<D: Distribution + ?Sized>(
    &self, new_data: &DataSet, family: &D, p: &Array1<f64>,
) -> Result<Array1<f64>, GamlssError> {
    let params_owned = self.predict(new_data, family)?;
    let params: HashMap<&str, &Array1<f64>> =
        params_owned.iter().map(|(k, v)| (k.as_str(), v)).collect();
    family.quantile(p, ¶ms)
}

Centiles are literally "predict then quantile" — no new linear-algebra path, since predict already does design-matrix assembly + inv_link.

Tests

  • For a symmetric family the 50th centile equals the fitted μ (i.e. predict's mu).
  • Centiles strictly increasing in α at every row (monotone quantile).
  • Coverage: simulate from the fitted model; the empirical fraction of y below C_α ≈ α — the same property INFER-1 checks from the residual side.

TRAIT-2 — mu_eta derivative on the Link trait

File: src/distributions/links.rs. Independent of TRAIT-1 / INFER-1 / INFER-2.

Why the link needs a derivative

The Rigby–Stasinopoulos inner loop is Fisher scoring for each parameter on its η-scale. Glissando's derivatives returns the score u and Fisher weight w already on the η-scale, which forces every family to bake in its specific link. The chain rule is what couples the two scales:

uη = ∂l/∂η = (∂l/∂θ)·(dθ/dη) = (∂l/∂θ)· mu_eta wη = E[(∂l/∂η)²] = (dθ/dη)²·E[(∂l/∂θ)²] = mu_eta²· iθ working variate: z = η + uη / wη

where mu_eta = dθ/dη = (g⁻¹)'(η) and i_θ is the Fisher information on the natural (response) scale. With mu_eta available, a family can return the link-agnostic pair (∂l/∂θ, i_θ) and the engine multiplies by mu_eta / mu_eta² to land on the η-scale — so a parameter can take any link without the family re-deriving its weights. That is the prerequisite the LINK-* expansion (probit, cloglog, inverse, sqrt, …) consumes.

Closed-form check — Gaussian σ with the log link. Here θ=σ, η=log σ, so mu_eta = dσ/dη = σ. On the natural scale ∂l/∂σ = ((y−μ)² − σ²)/σ³ and i_σ = 2/σ². Then

uη = σ · ((y−μ)² − σ²)/σ³ = ((y−μ)² − σ²)/σ²,   wη = σ²·(2/σ²) = 2

which is exactly the u_sigma / w_sigma = 2 currently hard-coded in gaussian.rs. Same check for μ (identity link, mu_eta = 1) returns (y−μ)/σ² and 1/σ². The math reproduces the existing weights — confirming mu_eta is the right hinge.

Code

Add the method with a finite-difference default (keeps external Link impls compiling — a minor, non-breaking change), then override on the four built-ins:

// in `pub trait Link`  (src/distributions/links.rs)

/// Derivative of the inverse link wrt the linear predictor: `dμ/dη = (g⁻¹)'(η)`.
/// Generic IRLS weights are `mu_eta(η)² · i_θ`; supplying this analytically lets
/// the scoring step build η-scale weights for *any* link.
///
/// Default: symmetric finite difference, so external impls keep compiling.
fn mu_eta(&self, eta: f64) -> f64 {
    let h = 1e-6;
    (self.inv_link(eta + h) - self.inv_link(eta - h)) / (2.0 * h)
}
impl Link for IdentityLink {  fn mu_eta(&self, _eta: f64) -> f64 { 1.0 } }          // μ = η

impl Link for LogLink {                                                            // μ = e^η ⇒ dμ/dη = μ
    fn mu_eta(&self, eta: f64) -> f64 { eta.min(MAX_ETA).exp() }
}

impl Link for FlooredLogLink {                                                     // 0 where floored, else e^η
    fn mu_eta(&self, eta: f64) -> f64 {
        let mu = eta.min(MAX_ETA).exp();
        if mu <= self.floor { 0.0 } else { mu }
    }
}

impl Link for LogitLink {                                                          // μ = σ(η) ⇒ dμ/dη = μ(1−μ)
    fn mu_eta(&self, eta: f64) -> f64 {
        let m = self.inv_link(eta);
        m * (1.0 - m)
    }
}

For reference, the closed forms the LINK-* item will add:

probit: μ = Φ(η),  mu_eta = φ(η) = e−η²/2/√(2π) cloglog: μ = 1 − e−e^η,  mu_eta = eη − e^η inverse: μ = 1/η,  mu_eta = −1/η² sqrt: μ = η²,  mu_eta = 2η

Scope discipline. TRAIT-2 is only the trait method + the four analytic overrides + tests. Do not rewrite the existing derivatives impls to route through mu_eta here — those η-scale weights are correct and finite-diff-verified (check_score_via_finite_diff). The generic-weight refactor belongs to the LINK-* item that actually needs non-canonical links; TRAIT-2 just lands the capability.

Tests

  • Each analytic mu_eta matches the finite-difference default to ~1e-6 across a grid of η (including the Log/Logit clamp regions) — mirrors the round-trip proptests in links.rs.
  • IdentityLink::mu_eta == 1 everywhere; LogitLink::mu_eta peaks at η=0 with value 0.25.
  • A regression test asserting the chain-rule reconstruction equals the hard-coded Gaussian (u, w) for both μ and σ (the closed-form check above), so the later refactor has a pinned target.
