glissando · smooth terms & splines

Implements SMOOTH-1 (cyclic splines, mgcv bs="cc"), SMOOTH-2 (thin-plate, bs="tp"), and SMOOTH-4 (random slopes). These are grouped because they all plug into the same three-touchpoint contract the existing P-spline / CR-spline / tensor / random-intercept smooths already follow — no change to the RS fitting loop, only new basis-and-penalty blocks.

Read the PSpline1D path first — its enum variant (src/terms.rs:189), its basis (src/splines/pspline.rs), and its assembler arm (src/fitting/assembler.rs:277) are the worked example every new smooth copies. This guide is the delta: what each new variant changes at each touchpoint.

The three-touchpoint contract

A smooth term is a Smooth enum variant that the assembler turns into a design-matrix block X_j plus one or more penalty matrices S_j. Adding a variant touches exactly three places — and because the assembler's match smooth { … } has no wildcard arm, the compiler will refuse to build until you have handled the new variant in all three:

  1. The enum — add a variant to Smooth (src/terms.rs:189–240) carrying its column name(s) and hyper-parameters, plus a constructor in impl Smooth (alongside ps/cr/re/tensor at terms.rs:256–287).
  2. The basis — add a pub(crate) fn in src/splines/ that returns the basis Array2<f64> and its penalty, mirroring pspline.rs::create_basis_matrix (:15) + penalty.rs::create_penalty_matrix (:7).
  3. The assembler — add a match arm to each of three functions in src/fitting/assembler.rs: assemble_basis_and_penalty (:276–395, builds (X_j, vec![S_j])), null_space_dim (:58–99, the penalty's unpenalized rank), and — only if a field resolves from data — resolve_term (:119–135).

The reference arm to copy, verbatim from assembler.rs:277. The sum-to-zero reparameterization (reparam.rs::sum_to_zero_basis, :18) is applied whenever an intercept is present, so the smooth is identifiable:

Smooth::PSpline1D { col_name, n_splines, degree, penalty_order } => {
    let x_col = get_col(data, col_name)?;
    let basis = create_basis_matrix(x_col, *n_splines, *degree);
    let penalty = create_penalty_matrix(*n_splines, *penalty_order);

    if apply_constraint && *n_splines >= 2 {
        let z = sum_to_zero_basis(*n_splines);
        let basis_c = basis.dot(&z);
        let penalty_c = z.t().dot(&penalty).dot(&z);
        Ok((basis_c, vec![PenaltyMatrix(penalty_c)]))
    } else {
        Ok((basis, vec![PenaltyMatrix(penalty)]))
    }
}

SMOOTH-1 · Cyclic spline (mgcv bs="cc")

A cyclic spline forces the fitted curve and its derivatives to match at the two ends of the range — for seasonal / periodic covariates (day-of-year, hour-of-day) where January and December are neighbours. Mechanically it is a P-spline whose basis columns wrap around and whose difference penalty is circulant.

Touchpoint 1 — the variant. Carries the data range like CrSpline1D carries its knots: resolved once at fit, replayed at predict.

/// 1D cyclic P-spline (mgcv `bs = "cc"`): curve wraps over the period.
CyclicPSpline1D {
    col_name: String,
    n_splines: usize,
    degree: usize,
    penalty_order: usize,
    /// (min, max) of the period; empty `None` until `resolve_term` fills it.
    range: Option<(f64, f64)>,
},

Touchpoint 2 — the basis, a new src/splines/cyclic.rs. Build the ordinary equally-spaced B-spline basis, then fold the trailing degree columns onto the leading ones so the basis is periodic; the penalty is the order-d difference operator made circulant (its rows wrap):

Touchpoint 3 — the assembler. The arm is the PSpline1D arm with the cyclic basis/penalty and a resolved range; null_space_dim returns 0 (after centering, the circulant penalty's lone constant null vector is removed by sum-to-zero). Resolve the range in resolve_term exactly as CrSpline1D resolves its knots:

// assemble_basis_and_penalty:
Smooth::CyclicPSpline1D { col_name, n_splines, degree, penalty_order, range } => {
    let (lo, hi) = range.ok_or_else(|| GamlssError::Internal(
        format!("CyclicPSpline1D range for '{}' unresolved; call resolve_terms first", col_name)))?;
    let x_col = get_col(data, col_name)?;
    let basis = create_cyclic_basis_matrix(x_col, *n_splines, *degree, lo, hi);
    let penalty = create_cyclic_penalty_matrix(*n_splines, *penalty_order);
    if apply_constraint && *n_splines >= 2 {
        let z = sum_to_zero_basis(*n_splines);
        Ok((basis.dot(&z), vec![PenaltyMatrix(z.t().dot(&penalty).dot(&z))]))
    } else {
        Ok((basis, vec![PenaltyMatrix(penalty)]))
    }
}

// null_space_dim:
Smooth::CyclicPSpline1D { .. } => 0,

// resolve_term (fill range from data once, like CrSpline1D knots):
Term::Smooth(Smooth::CyclicPSpline1D { col_name, range, .. }) if range.is_none() => {
    let x = get_col(data, col_name)?;
    let lo = x.iter().cloned().fold(f64::INFINITY, f64::min);
    let hi = x.iter().cloned().fold(f64::NEG_INFINITY, f64::max);

Oracle: mgcv s(x, bs="cc") on a periodic covariate; the cleanest correctness check is that the fitted curve and its first derivative agree at lo and hi to numerical tolerance.

SMOOTH-2 · Thin-plate regression spline (mgcv bs="tp")

The default mgcv 2D smoother: an isotropic surface f(x₁, x₂) that needs no knot placement — the basis is built from radial functions centred at the data, then truncated to k columns by an eigen-decomposition that keeps the k most wiggly directions. It is the heaviest item here because of that eigen step (routed through the linalg backend), and unlike the tensor product it is genuinely rotation-invariant.

Touchpoint 1 — the variant:

/// 2D thin-plate regression spline (mgcv `bs = "tp"`): isotropic f(x₁, x₂),
/// truncated to `k` basis functions via eigen-reduction.
ThinPlate2D {
    col_name_1: String,
    col_name_2: String,
    k: usize,
},

Touchpoint 2 — the basis, a new src/splines/tp.rs. The thin-plate radial kernel in 2D is η(r) = r²·ln r. Form the n×n kernel matrix E over the observations and the polynomial null-space block T = [1, x₁, x₂] (dimension 3); the wiggliness penalty is E itself in the radial block. Reduce to rank k by truncating the eigen-decomposition of E (Wood 2003) — this is the one place that calls the backend:

use ndarray::{Array1, Array2};
use crate::linalg::symmetric_eigh;   // backend abstraction (openblas / nalgebra)

/// Truncated thin-plate basis + penalty for f(x1, x2).

Touchpoint 3 — the assembler. The wiggly block is penalized, the 3 polynomial columns are not, so null_space_dim = 3. Sum-to-zero centering still applies to remove the constant when an intercept is present:

// assemble_basis_and_penalty:
Smooth::ThinPlate2D { col_name_1, col_name_2, k } => {
    let x1 = get_col(data, col_name_1)?;
    let x2 = get_col(data, col_name_2)?;
    let (basis, penalty) = create_thinplate_basis(x1, x2, *k);
    // centering optional here — the null space already excludes pure wiggliness;
    // mirror the TensorProduct arm if you also strip the constant column.
    Ok((basis, vec![PenaltyMatrix(penalty)]))
}

SMOOTH-4 · Random slopes

Today only random intercepts exist (RandomEffect). A random slope lets a continuous covariate's effect vary by group — x with a per-group coefficient b_g ~ N(0, 1/λ) — which is the random-intercept basis with every indicator column scaled by x. It reuses the ridge-penalty machinery wholesale.

Touchpoint 1 — the variant:

/// Random slope: covariate `x_col` with a per-group coefficient, b_g ~ N(0, 1/λ).
RandomSlope {
    group_col: String,
    x_col: String,
},

Touchpoints 2 & 3 — basis + assembler in one. No new splines/ function is needed: the existing RandomEffect arm (assembler.rs:387) builds the group-indicator matrix; multiply each row by its x value and keep the identity (ridge) penalty. null_space_dim = 0:

// assemble_basis_and_penalty — the RandomEffect arm with one extra line:
Smooth::RandomSlope { group_col, x_col } => {
    let group_var = get_col(data, group_col)?;
    let x = get_col(data, x_col)?;

    let mut group_to_id: HashMap<String, usize> = HashMap::new();
    for val in group_var.iter() {
        let next_id = group_to_id.len();
        group_to_id.entry(val.to_string()).or_insert(next_id);
    }
    let n_groups = group_to_id.len();

    let mut basis = Array2::<f64>::zeros((n_obs, n_groups));
    for (i, val) in group_var.iter().enumerate() {
        if let Some(&g) = group_to_id.get(&val.to_string()) {
            basis[[i, g]] = x[i];          // ← slope: indicator × covariate
        }
    }
    let penalty = Array2::<f64>::eye(n_groups);   // ridge ⇒ b_g ~ N(0, 1/λ)
    Ok((basis, vec![PenaltyMatrix(penalty)]))
}

// null_space_dim:
Smooth::RandomSlope { .. } => 0,

Oracle: R gamlss re() / lme4 (x | g); recover known per-group slopes from simulated data. A correlated random intercept-and-slope is the natural follow-on — two penalty blocks instead of one — but ship the diagonal version first.

Tests & reference oracle

Each new basis is independently testable before any fit:

  • Basis shape & rank — create_* returns the documented n × width; numerical rank equals width minus null_space_dim.
  • Penalty symmetry & null space — S = Sᵀ, positive semi-definite, with exactly null_space_dim zero eigenvalues (cyclic: 1 before centering, 0 after; thin-plate: 3; random slope: 0).
  • Cyclic continuity — fitted curve and first derivative agree at the two ends of the range.
  • Recovery — simulate a known smooth (a sinusoid for cyclic, a Gaussian bump for thin-plate, known slopes for random slopes), fit, assert the fitted values track the truth.
  • mgcv parity (tests/mgcv_reference.rs style, #[ignore]) — add bs="cc" / bs="tp" / re() scenarios to benchmark/run_comparison.sh; compare fitted curves and EDF.
