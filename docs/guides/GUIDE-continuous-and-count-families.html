glissando · continuous & count families

Implements DIST-2 (continuous-positive), DIST-3 (skew / kurtotic continuous), and DIST-4 (count families): the bulk of what gamlss.dist ships. I grouped them together because they all plug into the existing Distribution trait with no new fitting machinery. Each is one struct, one file, registered by name. Structural changes (atoms, censoring, mixtures) live in the sibling guides.

Read the shipped Box-Cox family first (src/distributions/bccg.rs / bct.rs / bcpe.rs). It is the worked example of every Distribution method, and the template all of these copy. This guide is the catalog: what each group needs on top of that template, and the build order that lands the cheap wins before the hard ones.

The trait, recapped

A family is a struct implementing Distribution (src/distributions/mod.rs:41). Copy the file shape of the closest existing family and fill in: parameters(), default_link(), derivatives() (score u + Fisher w on the η scale), loglik_pointwise(), cdf(), quantile(), variance(), name(), and is_discrete() / expected_value() / initial_value() where the defaults are wrong. The defaults give you pdf (= exp(loglik), mod.rs:105), loglik (sum), and expected_value = μ (mod.rs:78) for free.

The derivatives() contract is the heart of every family: a HashMap keyed by parameter name, each entry holding the η-scale score u and Fisher weight w as aligned Array1<f64> columns.

fn derivatives(&self, y: &Array1<f64>, params: &HashMap<&str, &Array1<f64>>)
    -> DerivativesResult
{
    // …compute u_p, w_p per parameter on the η = link(θ) scale…
    Ok(HashMap::from([
        ("mu".to_string(),    (u_mu, w_mu)),
        ("sigma".to_string(), (u_sigma, w_sigma)),
    ]))
}

For a fully worked DIST-2 family in copy-paste Rust (Weibull, every method end to end plus the four-surface registration and tests), see the companion continuous-positive worked guide. This guide is the catalog around it.

Closest templates by shape: gamma.rs / poisson.rs (1–2 params), student_t.rs and the Box-Cox files (3–4 params with ν/τ), poisson.rs again for the discrete CDF/quantile contract. Special-function helpers are already vendored: statrs::function::gamma::{ln_gamma, digamma, gamma_ur}, statrs::function::beta::beta_reg, and the vectorized par_zip_map / par_zip3_map + digamma/trigamma in src/math.rs.

DIST-2 · continuous-positive (the easy wins)

Families: Lognormal (LOGNO), Exponential, Weibull (WEI), Inverse Gaussian (IG), Generalized Gamma (GG), Pareto. Support is y > 0; is_discrete() stays false.

Shared spine: a log link on μ (positive scale), and these are the families that exercise the just-shipped canonical links LINK-3 (inverse, Gamma), LINK-4 (inverse-square, IG), LINK-5 (sqrt), all shipped in src/distributions/links.rs; selecting them is a default_link choice, nothing more. Override expected_value whenever the mean ≠ μ (e.g. Lognormal mean exp(μ+σ²/2), Weibull mean μ·Γ(1+1/σ)) and variance for honest Pearson residuals.

Order within the group: Exponential (1 param) and Lognormal (reuses the Gaussian density on log y + a Jacobian) are the cheap first wins, both a few lines over gamma.rs. Weibull and IG are 2-parameter and have closed-form cdf/quantile. GG (3-param) generalizes Gamma/Weibull/Lognormal and is the capstone; Pareto is heavy-tailed and wants robust seeds in initial_value.

DIST-3 · skew / kurtotic continuous

Families: Skew Normal (SN1/SN2), Skew-t (ST1–ST5), Sinh-Arcsinh (SHASH), Johnson SU (JSU), Power Exponential (PE), Generalized t (GT). These carry 3–4 parameters: location μ, scale σ, skew ν, kurtosis τ.

Shared spine: the closest template is student_t.rs and the Box-Cox bct.rs / bcpe.rs files, which share the μ/σ/ν(/τ) layout, identity-or-log links per parameter, and robust median/MAD seeds in initial_value. The mean is generally ≠ μ, so expected_value must be overridden (or, where no closed form exists, documented as median-centered). The kurtotic densities (PE, SHASH) need the same lgamma / normalizing-constant machinery the BCPE family already uses. The derivative columns are the heavy step. Validate every derivatives() against a finite-difference of loglik_pointwise (helper below) before you trust it; a wrong score silently degrades the fit rather than erroring.

DIST-4 · count families

Families: Geometric, Logarithmic, Beta-Binomial (BB), Double Poisson, Poisson-Inverse-Gaussian (PIG), Sichel, Delaporte.

Shared spine, the discrete contract: set is_discrete() → true (this routes the de-lumping branch of INFER-1 randomized-quantile residuals, which needs both F(y) and F(y−1)). Implement quantile via the shared discrete_quantile(p, |k| cdf_at(k)) helper (mod.rs:215, doubling-bracket then bisection, copy poisson.rs:92). The cdf must satisfy cdf(k) − cdf(k−1) = pmf(k) at integer support; the test helper check_discrete_cdf_matches_pmf enforces exactly this. Where a closed-form CDF exists use it (Poisson uses gamma_ur, Binomial uses beta_reg); otherwise sum the pmf with a running guard. PIG / Sichel / Delaporte are over-dispersed mixtures and need their recursive pmf, the heaviest items here; Geometric and Logarithmic are the cheap entry points.

Build order

  1. Pick the cheapest family in the target group (Exponential / Lognormal for DIST-2, SN for DIST-3, Geometric for DIST-4). New file src/distributions/<name>.rs; copy the closest template's struct + Default + trait skeleton; register the module + pub use in src/distributions/mod.rs (the block at mod.rs:244).
  2. Transform + likelihood first. Implement loglik_pointwise, cdf, quantile (continuous: closed-form invert; discrete: discrete_quantile). These are independently testable and unblock pdf + centiles before any derivative work.
  3. Derivatives (the heavy step). Return score/Fisher per parameter on the η scale. Validate against finite differences with check_score_via_finite_diff before trusting it. Put the full ∂/∂μ, ∂/∂σ, … derivations in docs/math/mathematics.md §1 alongside the existing families.
  4. Override the defaults that are wrong. expected_value wherever mean ≠ μ; variance for Pearson residuals; initial_value for robust seeds; is_discrete → true for counts.
  5. Register in the factory + bindings. Add the name to from_name (mod.rs:298) and the surfaces below, then move to the next family in the group, where only h(z) / the extra parameter / its derivative column change.

Tests & reference oracle

Oracle: R gamlss / gamlss.dist. This is the like-for-like Rigby-Stasinopoulos oracle with the same parameterization (dIG/pIG/qIG, dWEI, dLOGNO, dSICHEL, dPIG, dSHASH, …). Learn from the project's StudentT experience and compare against the matching gamlss family, not mgcv. Reuse the existing helpers in src/distributions/mod.rs::test_helpers:

  • check_score_via_finite_diff: analytic score vs central difference of loglik_pointwise, on the η scale, at random parameter values.
  • check_cdf_quantile_roundtrip (continuous): Q(F(y)) ≈ y.
  • check_cdf_pdf_consistency (continuous): dF/dy ≈ pdf(y).
  • check_discrete_cdf_matches_pmf (counts): cdf(k) − cdf(k−1) ≈ pmf(k).
  • check_cdf_monotone_in_unit: cdf ∈ [0,1], non-decreasing.
  • derivative_keys_match_parameters: every parameter has a finite, non-negative-Fisher derivative entry.

Coefficient recovery (tests/correctness.rs style): simulate from known parameters via the family's quantile, fit, assert recovery. Parity (tests/mgcv_reference.rs style, #[ignore]): add a case to benchmark/run_comparison.sh / fit_gamlss.R and compare coefficients + fitted quantities.

Cross-surface bindings BIND-3

Surface each family exactly as the existing 11 are: add the name to from_name (src/distributions/mod.rs:298), which the JSON facade (src/json.rs) and WASM shim resolve through automatically, plus a Python distribution class in src/python.rs. Because every parameter of these families is fitted (none carry structural state like Binomial's n_trials or Ocat's n_categories), SER-1 does not bite: they round-trip through to_json / from_json by name. Add a per-distribution worked example (DOC-3).
