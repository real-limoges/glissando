glissando · continuous-positive, worked end-to-end

Implements DIST-2 by writing one family in full, Weibull (WEI): every Distribution method, the registration across all four surfaces, and the tests, as copy-paste Rust. The other DIST-2 families (Lognormal, Exponential, Inverse Gaussian, Generalized Gamma, Pareto) are then a short delta table off this template. The catalog guide is the map of what to build; this is the how, in code.

The closest in-tree template is src/distributions/gamma.rs, with the same two parameters (μ, σ), both log-linked, with a closed-form CDF and quantile. Read it once; this guide reuses its exact shape so a diff against it is small.

1 · The Weibull parameterization

Match R gamlss WEI(mu, sigma) so the parity fixtures line up: μ > 0 is the scale, σ > 0 the shape, support y > 0. Writing z = (y/μ)^σ (so z ~ Exponential(1) at the true parameters):

pdf       f(y)  = (σ/μ)·(y/μ)^(σ−1)·exp(−z)
loglik    ℓ     = ln σ − σ·ln μ + (σ−1)·ln y − z
cdf       F(y)  = 1 − exp(−z)
quantile  Q(p)  = μ·(−ln(1−p))^(1/σ)
mean      E[Y]  = μ·Γ(1 + 1/σ)            // ≠ μ, so override expected_value
var       V[Y]  = μ²·[Γ(1 + 2/σ) − Γ(1 + 1/σ)²]

The RS loop consumes a score u and Fisher weight w on the η scale, and both parameters take a LogLink, so with z = (y/μ)^σ and Euler's constant γ ≈ 0.5772 those work out to:

μ (η = ln μ):  u_μ = σ·(z − 1)                  w_μ = σ²
σ (η = ln σ):  u_σ = 1 + σ·ln(y/μ)·(1 − z)      w_σ = π²/6 + (1 − γ)²  ≈ 1.8237

These are not what the family returns. derivatives stops one step earlier, at the natural scale, and the chain rule above is reapplied generically from whatever link the caller selected. §2 gives the natural-scale forms; keep these two lines as the answer to check them against.

Two things make Weibull a clean worked example: E[u_μ] = E[u_σ] = 0 falls out of E[z] = 1 and E[z·ln z] = 1 − γ, and the shape Fisher weight w_σ is a parameter-free constant. The full ∂/∂μ, ∂/∂σ working belongs in docs/math/mathematics.md §1 alongside the other families.

2 · The file: src/distributions/weibull.rs

Header + struct. Mirror gamma.rs's imports; Weibull needs ln_gamma for the moment overrides and the standard math helpers for the vectorized columns.

//! Weibull distribution for positive continuous data.

use super::{
    require, DerivativesResult, Distribution, GamlssError, Link, LogLink, DENOM_FLOOR,
    MIN_POSITIVE,
};
// Note: no `MIN_WEIGHT`. Families never floor; see the derivatives section below.
use crate::math::{par_zip3_map, par_zip_map};
use ndarray::Array1;
use statrs::function::gamma::ln_gamma;
use std::collections::HashMap;

/// Weibull distribution (gamlss `WEI` parameterization).
///
/// Parameters: `μ` (scale, log link) and `σ` (shape, log link). Support `y > 0`.
/// With `z = (y/μ)^σ`, `Var(Y) = μ²·[Γ(1+2/σ) − Γ(1+1/σ)²]` and the mean is
/// `μ·Γ(1+1/σ)`; neither equals `μ`, so both moment methods are overridden.
#[derive(Debug, Clone, Copy, Default)]
pub struct Weibull;

impl Weibull {
    pub fn new() -> Self {
        Self
    }
}

Parameters, links, seeds. Both log-linked. The default initial_value (mean for μ, SD for σ) is wrong for a shape parameter, exactly as it was for Gamma's CV. Seed σ at 1.0 (the Exponential special case, where μ ≈ mean(y)) and let the RS loop move it.

impl Distribution for Weibull {
    fn parameters(&self) -> &[&'static str] {
        &["mu", "sigma"]
    }

    fn default_link(&self, param: &str) -> Result<Box<dyn Link>, GamlssError> {
        match param {
            "mu" | "sigma" => Ok(Box::new(LogLink)),
            other => Err(self.unknown_param(other)),
        }
    }

    /// σ is the Weibull shape; the default `y.std()` seed is meaningless for it.
    /// Seed σ = 1 (Exponential), where the scale μ ≈ mean(y); RS refines both.
    fn initial_value(&self, param: &str, y: &Array1<f64>) -> f64 {
        match param {
            "mu" => y.mean().expect("validate_inputs rejects empty y"),
            "sigma" => 1.0,
            _ => 0.1,
        }
    }

Derivatives. Stop at the natural scale: return (∂l/∂θ, i_θ) and let the generic chain rule reach η. Two rules matter here and both are easy to get wrong.

  • Do not fold the link in. §1 derives the η-scale columns, and it is tempting to return those; a family that does will double-chain once eta_derivatives_via_chain! multiplies by mu_eta. The η forms are what you check your work against, not what you return.
  • Do not floor. MIN_WEIGHT is applied once, downstream, after the multiply, because max(mu_eta²·i_θ, F) ≠ mu_eta²·max(i_θ, F). Flooring here can be wrong by many orders of magnitude for a parameter whose mu_eta is large.

Un-folding reintroduces the 1/μ and 1/σ that the η forms cancelled, so guard each denominator at the power it is actually used at: squaring an already-guarded reciprocal overflows to infinity for a parameter the log link can still underflow to, and inf · 0 is NaN. Guard the denominator, never the parameter, since the caller's mu_eta is computed from η independently of anything you clamp.

    fn derivatives(
        &self,
        y: &Array1<f64>,
        params: &HashMap<&str, &Array1<f64>>,
    ) -> DerivativesResult {
        // z = (y/μ)^σ ~ Exp(1) at the truth. Natural scale:
        //   μ: ∂l/∂μ = σ(z−1)/μ,                 i_μ = σ²/μ².
        //   σ: ∂l/∂σ = [1 + σ·ln(y/μ)·(1−z)]/σ,  i_σ = (π²/6 + (1−γ)²)/σ².
        // Both default links are log, so chain_to_eta (mu_eta = μ, σ) recovers
        // the η forms of §1: u_μ = σ(z−1), w_μ = σ², and the constant w_σ.
        let mu = require(self, params, "mu")?;
        let sigma = require(self, params, "sigma")?;

        const EULER: f64 = 0.577_215_664_901_532_9;
        let i_sigma_numer = std::f64::consts::PI.powi(2) / 6.0 + (1.0 - EULER).powi(2);

        let inv_mu = mu.mapv(|m| 1.0 / m.max(DENOM_FLOOR));
        let inv_mu_sq = mu.mapv(|m| 1.0 / (m * m).max(DENOM_FLOOR));
        let inv_sigma = sigma.mapv(|s| 1.0 / s.max(DENOM_FLOOR));
        let inv_sigma_sq = sigma.mapv(|s| 1.0 / (s * s).max(DENOM_FLOOR));

        let u_mu = par_zip3_map(y, mu, sigma, |yi, mui, si| {
            let m = mui.max(MIN_POSITIVE);
            let z = (yi.max(MIN_POSITIVE) / m).powf(si);
            si * (z - 1.0)
        }) * &inv_mu;
        let i_mu = par_zip_map(sigma, &inv_mu_sq, |s, ims| (s * s) * ims);

        let u_sigma = par_zip3_map(y, mu, sigma, |yi, mui, si| {
            let m = mui.max(MIN_POSITIVE);
            let r = yi.max(MIN_POSITIVE) / m;
            let z = r.powf(si);
            1.0 + si * r.ln() * (1.0 - z)
        }) * &inv_sigma;
        let i_sigma = inv_sigma_sq.mapv(|iss| i_sigma_numer * iss);

        Ok(HashMap::from([
            ("mu".to_string(), (u_mu, i_mu)),
            ("sigma".to_string(), (u_sigma, i_sigma)),
        ]))
    }

    // The η-scale adapter the scoring loop actually calls. One line for any
    // family with a separable natural scale; the macro expands to
    // `chain_to_eta(self.derivatives(y, params)?, ctx)`.
    eta_derivatives_via_chain!();

Log-likelihood, variance, mean. The mean and variance both involve Γ; compute it via exp(ln_gamma(·)).

    fn loglik_pointwise(
        &self,
        y: &Array1<f64>,
        params: &HashMap<&str, &Array1<f64>>,
    ) -> Result<Array1<f64>, GamlssError> {
        let mu = require(self, params, "mu")?;
        let sigma = require(self, params, "sigma")?;
        Ok(par_zip3_map(y, mu, sigma, |yi, mui, si| {
            let yv = yi.max(MIN_POSITIVE);
            let m = mui.max(MIN_POSITIVE);
            let z = (yv / m).powf(*si);
            si.ln() - si * m.ln() + (si - 1.0) * yv.ln() - z
        }))
    }

    fn expected_value(
        &self,
        params: &HashMap<&str, &Array1<f64>>,
    ) -> Result<Array1<f64>, GamlssError> {
        let mu = require(self, params, "mu")?;
        let sigma = require(self, params, "sigma")?;
        // E[Y] = μ·Γ(1 + 1/σ).
        Ok(par_zip_map(mu, sigma, |m, s| {
            m * ln_gamma(1.0 + 1.0 / s.max(MIN_POSITIVE)).exp()
        }))
    }

    fn variance(&self, params: &HashMap<&str, &Array1<f64>>) -> Result<Array1<f64>, GamlssError> {
        let mu = require(self, params, "mu")?;
        let sigma = require(self, params, "sigma")?;
        // V[Y] = μ²·[Γ(1+2/σ) − Γ(1+1/σ)²].
        Ok(par_zip_map(mu, sigma, |m, s| {
            let s = s.max(MIN_POSITIVE);
            let g1 = ln_gamma(1.0 + 1.0 / s).exp();
            let g2 = ln_gamma(1.0 + 2.0 / s).exp();
            m * m * (g2 - g1 * g1)
        }))
    }

CDF, quantile. Both closed-form: no special functions, no discrete_quantile (Weibull is continuous). The CDF is 0 below the y > 0 support, as in gamma.rs.

    fn cdf(
        &self,
        y: &Array1<f64>,
        params: &HashMap<&str, &Array1<f64>>,
    ) -> Result<Array1<f64>, GamlssError> {
        let mu = require(self, params, "mu")?;
        let sigma = require(self, params, "sigma")?;
        Ok(par_zip3_map(y, mu, sigma, |yi, mui, si| {
            if *yi <= 0.0 {
                return 0.0; // support is y > 0
            }
            let z = (yi / mui.max(MIN_POSITIVE)).powf(*si);
            1.0 - (-z).exp()
        }))
    }

    fn quantile(
        &self,
        p: &Array1<f64>,
        params: &HashMap<&str, &Array1<f64>>,
    ) -> Result<Array1<f64>, GamlssError> {
        let mu = require(self, params, "mu")?;
        let sigma = require(self, params, "sigma")?;
        Ok(par_zip3_map(p, mu, sigma, |pi, mui, si| {
            let pc = pi.clamp(1e-12, 1.0 - 1e-12);
            mui * (-(1.0 - pc).ln()).powf(1.0 / si.max(MIN_POSITIVE))
        }))
    }

CDF parameter derivatives (optional). Supplied only for μ (exactly as gamma.rs does), so the structural wrappers (censoring/truncation) get an analytic column for the location and fall back to central differencing for σ. Same rule as derivatives: return natural-scale (∂F/∂θ, ∂²F/∂θ²) and let structural.rs chain. With z = (y/μ)^σ and ∂z/∂μ = −σz/μ:

    fn cdf_theta_derivatives(
        &self,
        y: &Array1<f64>,
        params: &HashMap<&str, &Array1<f64>>,
    ) -> super::CdfThetaResult {
        // F = 1 − e^(−z), z = (y/μ)^σ.  ∂F/∂μ  = −σ·z·e^(−z)/μ
        //                               ∂²F/∂μ² = σ·z·e^(−z)·(1 + σ(1−z))/μ²
        // σ enters z non-elementarily through the exponent; left to the numeric fallback.
        let mu = require(self, params, "mu")?;
        let sigma = require(self, params, "sigma")?;
        let mut d1 = Array1::<f64>::zeros(y.len());
        let mut d2 = Array1::<f64>::zeros(y.len());
        for i in 0..y.len() {
            if !y[i].is_finite() || y[i] <= 0.0 {
                continue; // outside support or ±∞ bound: F flat, derivatives ≡ 0
            }
            let z = (y[i] / mu[i].max(MIN_POSITIVE)).powf(sigma[i]);
            let ez = (-z).exp();
            // Per-power guards, as in `derivatives` above.
            let denom1 = mu[i].max(DENOM_FLOOR);
            let denom2 = (mu[i] * mu[i]).max(DENOM_FLOOR);
            d1[i] = -sigma[i] * z * ez / denom1;
            d2[i] = sigma[i] * z * ez * (1.0 + sigma[i] * (1.0 - z)) / denom2;
        }
        Ok(HashMap::from([("mu".to_string(), (d1, d2))]))
    }

    fn name(&self) -> &'static str {
        "Weibull"
    }
}

Check the algebra by chaining back by hand. Under the log link mu_eta = mu_eta2 = μ, and the second-order rule ∂²F/∂η² = mu_eta²·∂²F/∂θ² + mu_eta2·∂F/∂θ gives σ·z·e^(−z)·(1 + σ(1−z)) − σ·z·e^(−z) = σ²·z·e^(−z)·(1−z), the η-scale form. If your natural expression does not telescope to an η one you derived independently, one of the two is wrong.

4 · Tests

Copy gamma.rs's inline mod tests shape and point the helpers (in src/distributions/mod.rs::test_helpers) at Weibull. These run without R and catch every algebra slip in §1; a wrong score silently degrades the fit rather than erroring, so the finite-difference checks are the ones that matter most. Four of them below are load-bearing, and the last two exist because of the natural-scale contract:

  • check_score_via_finite_diff validates the default-link chain, but it is vacuous for an identity-linked parameter, where ∂l/∂η ≡ ∂l/∂θ. Weibull has none, so it bites here.
  • check_eta_score_via_finite_diff under a non-default link is the test that proves the family did not fold a link in. A family that returns η-scale values passes the first check and fails this one, by exactly the link-derivative factor.
  • A saturated-fixture test, because un-folding makes the divisions reachable arithmetic that the interior fixtures never touch. This is what catches an overflow before a square, or a reciprocal guarded at the wrong power.

5 · The rest of DIST-2 as deltas

Each remaining continuous-positive family is the Weibull file with a different likelihood column and, sometimes, a non-log canonical link. The LINK-3/LINK-4/LINK-5 column flags which exercise the shipped inverse / inverse-square / sqrt links; a default_link choice, nothing more.

ExponentialOne parameter (mu, log). Weibull with σ ≡ 1: drop the σ column entirely. The cheapest first win, at a few lines.
LognormalReuse the Gaussian density on ln y plus a −ln y Jacobian; cdf = Φ((ln y − μ)/σ), mean = exp(μ + σ²/2). Closest to a copy of gaussian.rs.
Inverse GaussianTwo-parameter; variance = μ³σ². The natural home for the inverse-square canonical link LINK-4; set it in default_link.
Gamma (shipped)Already in tree (gamma.rs); pairs with the inverse canonical link LINK-3. The other reference template.
Generalized GammaThree-parameter (μ, σ, ν) capstone that nests Gamma/Weibull/Lognormal; closest shape is the Box-Cox files bct.rs/bcpe.rs.
ParetoHeavy-tailed; wants robust median/MAD seeds in initial_value so the first RS step doesn't diverge.
