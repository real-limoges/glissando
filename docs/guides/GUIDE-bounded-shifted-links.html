glissando · bounded / shifted links

Implements LINK-7, the shifted / bounded "own"-logit link: a logit on the rescaled (μ−a)/(b−a) that maps an arbitrary open interval (a, b) onto the real line. It's the one piece of workstream B I left open after the six canonical links (LINK-1…LINK-6: probit, cloglog, inverse, inverse-square, sqrt, cauchit) shipped. I deferred it for exactly one reason: it is the only link that is not a zero-field unit struct. It carries its bounds as state, and that state ripples through name-based selection and serialization.

Touches: src/distributions/links.rs (the struct + analytic mu_eta), the by-name link lookup (link_from_name) and the JSON link parser (both of which assume stateless links today), and the link documentation on each binding surface.

Why it is not a unit struct

Every link shipped so far is a struct XLink;: zero fields, fully described by its type name, selectable by a single string ("probit", "logit", …). The bounded-logit link is the odd one out. Here (a, b) are parameters of the link itself, supplied by the analyst as the known physical bounds of a response that lives strictly inside (a, b): a proportion on a non-[0,1] scale, a measurement with hard physical limits. So the struct has to hold them:

pub struct ShiftedLogitLink { pub lower: f64, pub upper: f64 }

This is the same state problem the stateful distributions already solved: Binomial carries n_trials, Ocat carries n_categories, and the structural wrappers carry response-side vectors. Copy their pattern, not the unit-struct links'.

The math

Let w = b − a be the interval width and p = (μ − a)/w ∈ (0,1) the rescaled position. The link is an ordinary logit on p:

link    g(μ)   = ln( (μ−a) / (b−μ) )            // logit(p)
inv_link g⁻¹(η) = a + w / (1 + e^(−η))           // a + w·σ(η)
mu_eta   dμ/dη  = w · σ(η)·(1 − σ(η))            // w · σ'(η)

where σ is the logistic sigmoid. With a = 0, b = 1 it collapses exactly to LogitLink, so LogitLink (links.rs:128) is the literal template; wrap the affine rescale around it.

The full impl. Copy LogitLink's clamping verbatim, then wrap the affine rescale around it:

pub struct ShiftedLogitLink { pub lower: f64, pub upper: f64 }

impl ShiftedLogitLink {
    pub fn new(lower: f64, upper: f64) -> Self {
        assert!(lower < upper, "ShiftedLogitLink needs lower < upper");
        Self { lower, upper }
    }
}

impl Link for ShiftedLogitLink {
    fn link(&self, mu: f64) -> f64 {
        let w = self.upper - self.lower;
        let p = ((mu - self.lower) / w).clamp(MIN_POSITIVE, 1.0 - MIN_POSITIVE);
        (p / (1.0 - p)).ln().clamp(MIN_ETA, MAX_ETA)   // logit(p)
    }
    fn inv_link(&self, eta: f64) -> f64 {
        let w = self.upper - self.lower;
        let s = 1.0 / (1.0 + (-eta.clamp(MIN_ETA, MAX_ETA)).exp());   // σ(η)
        self.lower + w * s
    }
    fn mu_eta(&self, eta: f64) -> f64 {
        let w = self.upper - self.lower;
        let s = 1.0 / (1.0 + (-eta.clamp(MIN_ETA, MAX_ETA)).exp());
        w * s * (1.0 - s)                               // w · σ'(η)
    }
    fn name(&self) -> &'static str { "shifted_logit" }
}

Saturation guards (mandatory). Reuse the module constants at links.rs:11–15: clamp μ off the open boundaries with MIN_POSITIVE (so μ−a and b−μ never hit 0) and clamp η to [MIN_ETA, MAX_ETA] before exp, exactly as LogitLink does. Validate a < b at construction.

Build order

  1. Add the struct in links.rs. ShiftedLogitLink { lower, upper } + impl Link with the closed-form mu_eta above. Construct via ShiftedLogitLink::new(a, b) that asserts a < b. Re-export from src/distributions/mod.rs alongside the other link structs.
  2. Decide the name-selection story. link_from_name and the JSON link parser map a bare string to a unit struct, so they cannot carry (a, b). Two options; pick and document one. (a) Exclude it from link_from_name the way stateful distributions are excluded from from_name, constructed only through the typed API. (b) Extend the link-selection surface to a small struct/enum that carries the bounds (a { "link": "shifted_logit", "lower": a, "upper": b } JSON shape). Option (b) is the one that makes the link usable from the JSON / WASM / Python surfaces, and that is the real scope of this item.
  3. Serialization. If you take option (b), the saved model has to round-trip the bounds, not just a name; mirror how the FamilyDescriptor work serializes stateful families' parameters rather than their name. A bare-name round-trip silently loses (a, b).

Tests & reference oracle

Extend the existing mod tests in links.rs; it already has the scaffolding:

  • Analytic vs finite-difference mu_eta. Add a ShiftedLogitLink::new(a, b) instance to the analytic-vs-FD check (links.rs:483 uses an [&dyn Link] array; this link needs a concrete instance with chosen bounds). Closed form must match the finite difference to 1e-5 across the η grid.
  • Collapse to logit. Assert ShiftedLogitLink::new(0.0, 1.0) matches LogitLink on link, inv_link, and mu_eta across a grid; the cleanest correctness check there is.
  • Round-trip + range. Mirror log_link_round_trip_in_safe_range (links.rs:544): link(inv_link(η)) ≈ η in the safe range, and inv_link(η) ∈ (a, b) for all η including ±1e6.

External oracle: no base-R make.link equivalent, but R gamlss exposes the "own" link mechanism and bounded-response families; an affine-rescaled binomial()$linkfun / linkinv tabulated at a grid of η serves as the numeric oracle.
