glissando · implementation guide

Fitting-engine robustness — FIT-1 (step-halving / line-search on the global deviance) and FIT-2 (global-deviance outer convergence). Two coupled fixes to the Rigby–Stasinopoulos loop that share one new quantity: the global deviance evaluated inside the loop. IDs cross-reference docs/ROADMAP.html.

Where the loop is today (src/fitting/mod.rs::fit_gamlss):

  • Each outer cycle calls scoring::step per parameter, which returns a full Fisher-scoring update (β, η, μ, covariance, edf, …). The step is accepted as-is; the only safeguards are weight floors and fixed η-change step caps inside scoring (step_cap_hits) — neither references the likelihood.
  • Convergence is decided purely by a per-parameter relative coefficient change: update.max_diff / |β|scale < tolerance. The deviance is never computed during fitting.

Both gaps are closed by promoting the global deviance to a first-class quantity in the loop. One helper, two consumers:

global_deviance(family, y, weights, models)      ← the shared substrate
   ├──► FIT-1  guarantee each accepted step does not increase it  (monotone descent)
   └──► FIT-2  stop when it stops changing                        (objective-based convergence)

Why it matters. A raw Fisher-scoring step can overshoot badly on heavy-tailed / skew families (Student-t with small ν, Gamma/Beta near a boundary) — the unmodified update increases the deviance and the loop oscillates or diverges. And a Δβ-only stopping rule is a proxy for the wrong thing: it can stop early when coefficients drift slowly along a flat ridge, or never stop when they oscillate while the fit itself is stationary. Making the deviance authoritative fixes both, and is exactly what R gamlss's RS loop does (it converges on global-deviance change and step-halves).

Shared substrate — the global deviance

File: src/fitting/mod.rs (private helper used by the outer loop).

The quantity RS implicitly minimizes is the (prior-weighted) global deviance:

GD(θ) = −2·ℓ(θ) = −2 · Σi wi · log f(yi | θi)

where w_i are the prior weights (all-ones when unweighted — see fit_weighted's semantics). The model's current response-scale parameters live on each internal FittingParameter.mu, so the helper just assembles the params view and calls the family's pointwise log-density:

// src/fitting/mod.rs
fn global_deviance<D: Distribution + ?Sized>(
    family: &D,
    y: &Array1<f64>,
    prior_weights: Option<&Array1<f64>>,
    models: &IndexMap<String, FittingParameter>,
) -> Result<f64, GamlssError> {
    let params: HashMap<&str, &Array1<f64>> =
        models.iter().map(|(k, m)| (k.as_str(), &m.mu)).collect();
    let ll_pt = family.loglik_pointwise(y, ¶ms)?;             // per-observation log f
    let ll = match prior_weights {
        Some(w) => (&ll_pt * w).sum(),
        None    => ll_pt.sum(),
    };
    Ok(-2.0 * ll)
}

/// Same, but evaluating one parameter block at a *proposed* mu not yet committed
/// to `models` — used by step-halving to score a trial move.
fn global_deviance_with<D: Distribution + ?Sized>(
    family: &D, y: &Array1<f64>, prior_weights: Option<&Array1<f64>>,
    models: &IndexMap<String, FittingParameter>, param: &str, mu_override: &Array1<f64>,
) -> Result<f64, GamlssError> {
    let mut params: HashMap<&str, &Array1<f64>> =
        models.iter().map(|(k, m)| (k.as_str(), &m.mu)).collect();
    params.insert(param, mu_override);                            // swap in the trial block
    let ll_pt = family.loglik_pointwise(y, ¶ms)?;
    let ll = match prior_weights { Some(w) => (&ll_pt * w).sum(), None => ll_pt.sum() };
    Ok(-2.0 * ll)
}

FIT-1 — Step-halving / line-search on the global deviance

Files: src/fitting/mod.rs (outer loop) + src/fitting/scoring.rs (helper, where x_matrix/link already live).

Math

RS updates one parameter block at a time, holding the others fixed. For block k the scoring step proposes a full update β_knew; write the search direction and the ray of partial steps as

dk = βknew − βkold βk(α) = βkold + α·dk,  ηk(α) = Xk βk(α),  μk(α) = gk−1(ηk(α))

The Fisher-scoring direction solves the penalized weighted least-squares normal equations (XᵀWX + Sλ) dk = Xᵀ W (z − η) with W positive definite, so d_k is an ascent direction for the (penalized) log-likelihood in block k — equivalently a descent direction for the global deviance restricted to that block:

d/dα GD(βk(α)) |α=0 = −2 · gk′ · dk ≤ 0   ⟹   ∃ ᾱ > 0 :  GD(βk(α)) < GD(βk(0))  for all α ∈ (0, ᾱ]

So a backtracking line search — start at the full step α=1 and halve until the deviance does not increase — is guaranteed to terminate, and turns each cycle into a monotone descent. That monotonicity is what tames the overshoot on heavy-tailed/skew families.

Code

// src/fitting/scoring.rs
pub(super) struct Halved {
    pub beta: Coefficients, pub eta: Array1<f64>, pub mu: Array1<f64>, pub hits: usize,
}

/// Backtrack a proposed block update on the global deviance (others fixed).
/// Returns the accepted (possibly damped) step; `hits` = number of halvings.
pub(super) fn step_halving<D: Distribution + ?Sized>(
    family: &D, y: &Array1<f64>, prior_weights: Option<&Array1<f64>>,
    models: &IndexMap<String, FittingParameter>, param: &str,
    proposed: &Update, min_alpha: f64,
) -> Result<Halved, GamlssError> {
    let model = &models[param];
    let gd0  = global_deviance(family, y, prior_weights, models)?;       // GD at α = 0
    let dir  = &proposed.beta.0 - &model.beta.0;                         // d_k
    let (x, link) = (&model.x_matrix.0, &model.link);

    let (mut alpha, mut hits) = (1.0_f64, 0usize);
    loop {
        let beta_a = &model.beta.0 + &(alpha * &dir);
        let eta_a  = x.dot(&beta_a);
        let mu_a   = eta_a.mapv(|e| link.inv_link(e));
        let gd_a   = global_deviance_with(family, y, prior_weights, models, param, &mu_a)?;

        // accept on no-increase (small slack absorbs round-off), or at the floor.
        if gd_a <= gd0 + 1e-8 || alpha <= min_alpha {
            return Ok(Halved { beta: Coefficients(beta_a), eta: eta_a, mu: mu_a, hits });
        }
        alpha *= 0.5;
        hits  += 1;
    }
}

Wire it into the outer loop right after scoring::step, gated by a config flag:

// src/fitting/mod.rs — inside the per-parameter loop
let update = scoring::step(family, y, prior_weights, &models, param_name, config.criterion)?;

let accepted = if config.step_halving {
    scoring::step_halving(family, y, prior_weights, &models, param_name, &update, MIN_STEP_ALPHA)?
} else {
    scoring::Halved { beta: update.beta.clone(), eta: update.eta.clone(),
                      mu: update.mu.clone(), hits: 0 }
};

let model = models.get_mut(*param_name).unwrap();
model.beta = accepted.beta;
model.eta  = accepted.eta;
model.mu   = accepted.mu;
// covariance / edf / term_edf / lambdas keep the values scoring::step computed at the full step
model.lambdas    = update.lambdas;
model.covariance = Some(update.covariance);
model.edf        = update.edf;
model.term_edf   = update.term_edf;
// record accepted.hits into ParamDiagnostic.step_halving_hits

Relationship to the existing η step-caps. The current caps clamp the η move to a fixed band so exp(η) stays finite during evaluation — a finiteness guard with no view of the objective. FIT-1 is the monotonicity guard. They compose: the cap keeps each trial evaluation numerically sane, then step-halving accepts only a deviance-non-increasing step. Keep both; they solve different failure modes.

Covariance / EDF caveat. scoring::step computes the covariance and EDF at the full step (α=1). Near convergence the accepted α→1, so the stored covariance (used for SEs and the EDF reported to FitDiagnostics) is evaluated at the right point. During early halved cycles those quantities are transient and overwritten next cycle — acceptable, and matches how gamlss reports them at the converged step.

FIT-2 — Global-deviance outer convergence

File: src/fitting/mod.rs (outer loop) + a field on FitConfig / FitDiagnostics.

Math

The existing test measures parameter movement; the deviance test measures objective improvement. gamlss converges on the latter:

Δβ test (today):  maxk ‖Δβk‖∞ / ‖βk‖scale < tol GD test (new):    |GDc−1 − GDc| / (|GDc| + 0.1) < tolGD

The GD test is the more faithful stopping rule because it stops exactly when the fit stops improving, independent of how the coefficients are scaled or parameterized. The roadmap asks for it in addition to Δβ, so require both — a belt-and-suspenders gate that won't declare convergence while either signal still says "moving":

converged ⟺ (Δβ test passes) ∧ (GD test passes)

The +0.1 floor in the denominator keeps the relative test well-defined as GD → 0; skip the GD test on cycle 0 (no previous deviance yet).

Code

// src/fitting/mod.rs — around the outer loop
let mut gd_prev = f64::INFINITY;
let mut final_deviance = None;
let mut final_deviance_change = None;

for cycle in 0..config.max_iterations {
    let mut all_converged = true;                  // existing Δβ accumulator
    // … per-parameter scoring + step-halving (FIT-1) …
    //    `all_converged` is cleared by the existing per-parameter Δβ test.

    // FIT-2: global-deviance change after the full sweep.
    let gd = global_deviance(family, y, prior_weights, &models)?;
    let gd_rel = (gd_prev - gd).abs() / (gd.abs() + 0.1);
    let gd_converged = cycle > 0 && gd_rel < config.gd_tolerance;

    final_deviance = Some(gd);
    final_deviance_change = Some(gd_rel);
    gd_prev = gd;
    final_change = max_diff;
    final_iteration = cycle + 1;

    if all_converged && gd_converged {             // require BOTH
        converged = true;
        break;
    }
}

Config & diagnostics surface

Both FitConfig and FitDiagnostics derive serde, so new fields need #[serde(default)] for backward-compatible JSON:

// src/fitting/mod.rs
pub struct FitConfig {
    pub max_iterations: usize,
    pub tolerance: f64,                 // Δβ tolerance (unchanged)
    pub criterion: SmoothingCriterion,
    #[cfg_attr(feature = "serde", serde(default = "default_true"))]

    #[cfg_attr(feature = "serde", serde(default = "default_gd_tol"))]
    pub gd_tolerance: f64,              // FIT-2, default 1e-3
}

Testing

The headline guarantees are monotone descent and unchanged solutions on well-behaved data — both directly testable.

  • Monotone deviance (FIT-1): on a stress case that overshoots without damping (e.g. Student-t with small ν, or Gamma with a few extreme responses), assert the per-cycle global deviance is non-increasing: gd[c] ≤ gd[c−1] + 1e-6. Capture the per-cycle GD via a test hook or by reading final_deviance across truncated max_iterations runs.
  • Halving actually fires: the same stress case yields Σ step_halving_hits > 0 and still converges, whereas step_halving = false diverges or hits the iteration cap.
  • Regression parity: on well-conditioned Gaussian data the new path must reproduce the old fitted coefficients within a tight tolerance (when no halving is needed and both criteria agree). This protects the existing tests/ + mgcv_reference parity — FIT-1/FIT-2 improve robustness without moving the converged solution.
  • FIT-2 stopping: a model where Δβ keeps wiggling but the deviance is flat now converges via the GD gate in a sane iteration count; and a case where GD is still dropping is not declared converged even if Δβ momentarily dips below tolerance.
  • Config plumbing: gd_tolerance and step_halving round-trip through parse_config; defaults match FitConfig::default().

Scope. This item is the RS loop's own robustness — it deliberately does not touch the smoothing-parameter optimizers (REML/GCV L-BFGS, Fellner–Schall) or add a second fitting algorithm. The roadmap's FIT-3 (CG cross-parameter algorithm) and FIT-4 (grid / "magic" λ selection) are separate; FIT-1/FIT-2 are the prerequisites that make a monotone, deviance-anchored loop you can trust before layering those on.

  1. Shared helper — global_deviance / global_deviance_with + unit tests (weighted & unweighted). Tiny; unblocks both.
  2. FIT-2 — GD-change convergence + gd_tolerance + final_deviance diagnostics. Pure addition to the loop; lowest risk.
  3. FIT-1 — step_halving + outer-loop wiring + step_halving flag + step_halving_hits. The behavioral change; gated by a default-on flag so it can be toggled in tests.
