glissando · zero-inflated & Tweedie

Implements DIST-5 (zero-inflated / zero-adjusted), DIST-7 (Tweedie, the marquee zero-inflated continuous case), and DIST-6 (Ocat beyond 5 categories). I grouped them because they share one idea: a response that is a mixture of an atom and a base distribution, an exact spike of zeros (or zeros-and-ones) sitting on top of a count or continuous part.

The good news: these need no new fitting machinery. The mixing probability is just another distribution parameter with its own linear predictor, and the Rigby-Stasinopoulos loop already fits one predictor per parameter, exactly the way Ocat fits its threshold parameters today. Read the shipped Box-Cox family (src/distributions/bccg.rs / bct.rs / bcpe.rs) for the trait template, the worked example of every Distribution method. This guide covers the mixture-specific seams.

Shared spine: atom + base, fitted as extra parameters

A zero-inflated / zero-adjusted family declares its mixing probability as an extra entry in parameters() with a logit link. For example, ZIP is ["mu","sigma"] where μ is the Poisson rate (log link) and σ is the structural-zero probability (logit link). The fitting loop fits a full Xβ predictor for each; the only new code is the family's own derivatives / loglik_pointwise. This is the same multi-predictor pattern ocat.rs uses for its delta_k thresholds: "no new machinery is needed beyond what already drives the RS update for scalar parameters" (ocat.rs:9).

The log-likelihood branches on the atom. For zero-inflation (counts, mixture of a point mass at 0 and a full count distribution that can also emit 0):

P(Y=0) = π + (1−π)·g(0)
P(Y=k) = (1−π)·g(k)            for k ≥ 1

For zero-adjustment (semicontinuous: an atom at 0 plus a strictly-positive continuous part, which cannot emit 0):

P(Y=0) = π
f(Y=y) = (1−π)·g(y)            for y > 0   (g a positive-continuous density)

where g is the base family (Poisson, NB, Gamma, IG, Beta) and π the logit-linked mixing parameter. loglik_pointwise selects the branch per row on y == 0; cdf adds the atom mass below/at zero; variance and expected_value follow the mixture law of total variance (mean ≠ μ, so override both). For discrete bases set is_discrete() → true and reuse discrete_quantile.

In code, the per-row branch (here zero-inflation over a count base g, with π logit-linked as the family's second parameter) is a par_zip3_map that switches on y == 0 and works in log-space for stability:

fn loglik_pointwise(&self, y: &Array1<f64>, params: &HashMap<&str, &Array1<f64>>)
    -> Result<Array1<f64>, GamlssError>
{
    let mu = require(self, params, "mu")?;       // base rate (log link)
    let pi = require(self, params, "sigma")?;    // structural-zero prob (logit link)
    Ok(par_zip3_map(y, mu, pi, |yi, mui, pii| {
        let g0 = (-mui).exp();                   // g(0) for Poisson base = e^(−μ)
        if *yi == 0.0 {
            // P(Y=0) = π + (1−π)·g(0)
            (pii + (1.0 - pii) * g0).max(MIN_POSITIVE).ln()
        } else {
            // P(Y=k) = (1−π)·g(k);  add ln(1−π) to the base log-pmf
            (1.0 - pii).max(MIN_POSITIVE).ln() + base_log_pmf(*yi, *mui)
        }
    }))
}

Zero-adjustment (a positive-continuous base that cannot emit 0) is the same shape with the y == 0 arm returning ln π and the y > 0 arm returning ln(1−π) + base_logpdf. The derivative columns follow by differentiating each branch; validate with check_score_via_finite_diff per parameter.

DIST-5 · zero-inflated & zero-adjusted

Families: ZIP, ZINBI (zero-inflated Poisson / NB), ZAGA, ZAIG (zero-adjusted Gamma / Inverse Gaussian), and the inflated betas BEINF / BEZI / BEOI (atoms at 0 and/or 1). The zero-inflated pair reuses the existing poisson.rs / negative_binomial.rs densities for g; the zero-adjusted pair reuses the DIST-2 positive-continuous densities; BEINF reuses beta.rs with one or two boundary atoms.

Why it ships with residuals, not alone. From docs/planning/feature-brainstorm.md: ZIP is visibly broken under Pearson residuals (a spike of zeros plus a Poisson part is not remotely Gaussian), so shipping it without INFER-1 randomized-quantile residuals invites bug reports. INFER-1 is already shipped (GamlssModel::quantile_residuals, exposed on every surface), and its discrete de-lumping branch is exactly what makes ZIP look right. So the dependency is already satisfied; just point the worked example at it.

DIST-7 · Tweedie (the hard one)

Compound Poisson-Gamma: a sum of N ~ Poisson Gamma jumps, so P(Y=0) = exp(−λ) (an exact atom) and Y > 0 is continuous. The single highest-value real-world case (insurance claims, rainfall, e-commerce spend), and the reason it earns its own section: it has no closed-form density. With the power-variance parameter p ∈ (1,2), Var(Y) = φ·μ^p, and the density for y > 0 is an infinite series:

f(y) = (1/y)·W(y, φ, p)·exp{ (1/φ)·[ y·μ^(1−p)/(1−p) − μ^(2−p)/(2−p) ] }

where W is the Wright function evaluated by summing terms (or a saddlepoint approximation). The work here is numerics, not trait plumbing: a stable, convergent series evaluation of W (and its derivatives) belongs in src/math.rs alongside the existing digamma/trigamma; bound the term count, work in log-space, and validate against R's tweedie::dtweedie. Treat p as a fitted parameter (its own predictor, typically fixed or profiled) and the atom at 0 as in the shared spine. Flag this as the highest-effort item in the guide, closer to the Box-Cox derivative work than to the easy positive-continuous template.

DIST-6 · Ocat beyond 5 categories

Not a mixture, but it belongs with these because it is the other family that grows its parameter list at construction. Ocat::new currently assert!s 2..=5 (ocat.rs:44) and threshold_param_name hard-codes delta_1..delta_4 (ocat.rs:62). Generalizing means lifting the cap: generate threshold parameter names dynamically for arbitrary R (the score/Fisher math at ocat.rs:191 is already written as a loop over n_thresholds and does not assume a fixed count), and replacing the four-arm match with a generated-name scheme. parameters() returns &[&'static str], so arbitrary-length names need either an interned/leaked name pool or a small redesign of the parameter-name return type; call this out as the one real design decision.

Like Binomial, Ocat carries state (n_categories) that a name string cannot recover, so it stays excluded from from_name and the JSON/WASM string-dispatch routes (ocat.rs:15); see SER-1 below.

Build order

  1. Start with ZIP. It reuses poisson.rs wholesale for g and exercises the entire mixture spine (extra logit parameter, y==0 likelihood branch, atom in the CDF, is_discrete). New file src/distributions/zip.rs; register at src/distributions/mod.rs:244.
  2. Likelihood + CDF first. Branch loglik_pointwise on y==0; add the atom mass in cdf; quantile via discrete_quantile. Override expected_value / variance with the mixture moments.
  3. Derivatives for both parameters. Score/Fisher for μ and the mixing π on the η scale; validate each with check_score_via_finite_diff (it perturbs one parameter at a time, which works for multi-parameter families, as the ocat tests show).
  4. Fan out the mixture family: ZINBI (swap NB for Poisson), then ZAGA / ZAIG (positive-continuous base, zero-adjusted branch), then BEINF (beta base, 0/1 atoms).
  5. Tweedie as a focused mini-project: land the Wright-series numerics in src/math.rs with its own tests first, then the family on top. Ocat-∞ independently: lift the cap and the name scheme in ocat.rs.

Tests & reference oracle

Oracle: R gamlss ZIP() / ZINBI() / ZAGA() / BEINF() (same μ/σ/ν parameterization); for Tweedie the tweedie / statmod packages (dtweedie, tweedie.profile). Reuse src/distributions/mod.rs::test_helpers: check_score_via_finite_diff (each parameter), check_discrete_cdf_matches_pmf (ZIP/ZINBI), check_cdf_quantile_roundtrip + check_cdf_pdf_consistency (the continuous part of ZAGA/Tweedie, away from the atom), check_cdf_monotone_in_unit, and derivative_keys_match_parameters.

  • Atom probability: assert cdf(0) − cdf(0⁻) = P(Y=0) matches the mixture formula at known (μ, π).
  • Residual sanity: a ZIP fit's randomized-quantile residuals (INFER-1) are ≈ N(0,1) where Pearson residuals are visibly non-normal; the headline demo.
  • Tweedie numerics: dtweedie series matches R across p ∈ {1.1, 1.5, 1.9} and a range of y spanning the atom and the tail; coefficient recovery from simulated data.

Cross-surface bindings BIND-3

ZIP / ZINBI / ZAGA / ZAIG / BEINF and Tweedie are stateless (all parameters fitted), so add them to from_name (src/distributions/mod.rs:298) and they flow through the JSON facade (src/json.rs) and WASM shim for free, plus a Python class in src/python.rs. SER-1 does not bite them. Ocat-∞ is the exception: it carries n_categories and stays out of the name routes, so its round-trip is gated on SER-1 (serialize the parameter, not just the name), which this work makes more urgent. Ship a worked example for each (DOC-3): the ZIP residual demo and a Tweedie insurance-spend fit.
