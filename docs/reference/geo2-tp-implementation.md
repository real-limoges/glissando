# GEO-2 Implementation Guide: Thin-Plate Regression Spline in 2D

This is a step-by-step walkthrough of GEO-2 from decision `0009`: an isotropic smooth surface over two coordinates, mgcv's `s(x, y, bs = "tp")`.
Today the only two-dimensional smooth in glissando is the tensor product `te(x, y)`.
A tensor has one smoothing parameter per axis, so the fitted surface depends on how the coordinate axes happen to be oriented.
Its knot grid also spans the training bounding box, so basis functions outside the convex hull of the data are held up by the penalty alone.
For spatial data, where north is not more special than north-east, that is the wrong model.

GEO-2 adds `Smooth::ThinPlate2D`, a thin-plate regression spline (Wood 2003).
It has one smoothing parameter, a penalty that is the integrated bending energy of the surface, and that penalty is invariant to rotating, translating, or uniformly rescaling the coordinates.
The basis is built from the data's own locations, so it has no bounding box.

**Done criterion**: `mu ~ 1 + tp(x, y)` recovers a Gaussian bump with R² above 0.9 against the noiseless truth.
Rotating the coordinates, or multiplying them by 1e5, leaves the fitted values unchanged to 1e-6.
`sigma ~ tp(x, y)` fits.
Prediction on new points uses the stored basis, the term survives a JSON round trip, and `s(x, y)` and `s(x, y, bs="tp", k=30)` parse.

**Scope**: one new spline module, one new smooth type implementing `SmoothBasis`, two parser changes, and tests.
No new linear algebra: the existing `linalg::symmetric_eigh` does both decompositions, so no QR helper is added to either backend.

    src/terms.rs                  <- Smooth::ThinPlate2D(ThinPlate2D) variant, basis() arm, Smooth::tp, k() and max_knots() builders, py_parse two-column tuples

## 1. Layout

Like GEO-1, this adds a smooth, not a layer.
The difference from every existing smooth is how much work happens at resolve time: an eigendecomposition of an `n_k x n_k` matrix, done once at fit time and never again.

    ThinPlate2D { cols, k, max_knots, knots: [], transform: [], penalty: [] }
       |
       v  ThinPlate2D::resolve (fit time, once): the expensive part
    knots  = unique (x, y) pairs, subsampled to max_knots
    E      = kernel between knots              n_k x n_k
    U_k    = eigenvectors of E, k largest |eigenvalue|
    Z      = null basis of the constraint T' U_k delta = 0      k x (k-3)
    transform = U_k Z                          n_k x (k-3)    stored
    penalty   = Z' D_k Z, rescaled              (k-3) x (k-3)  stored
       |
       v  ThinPlate2D::assemble (fit AND predict time): cheap
    basis row at (x, y) = [ kernel(x, y; knots) . transform | 1?, x, y ]
    penalty block       = [ penalty  0 ]
                          [ 0        0 ]
       |
       v
    the existing PWLS solver and smoothing-parameter optimizer, unchanged

Prediction never decomposes anything.
It evaluates the kernel between the new points and the stored knots and multiplies by the stored transform.

## 2. Why this construction

A thin-plate spline in two dimensions minimizes

    sum_i (y_i - f(x_i))^2  +  lambda * J(f),
    J(f) = integral of (f_xx^2 + 2 f_xy^2 + f_yy^2) dx dy,

whose solution has the closed form

    f(x) = sum_j delta_j eta(|x - x_j|) + alpha_0 + alpha_1 x + alpha_2 y,   subject to T' delta = 0,

with one kernel function per data point, `eta(r) = r^2 ln(r) / (8 pi)`, and `T = [1, x, y]` evaluated at the data points.
`J` is invariant to rotation and translation, and scales by a constant under uniform rescaling, which is the isotropy GEO-2 is for.
The null space of `J` is the linear functions `{1, x, y}`, dimension 3.

One coefficient per data point is too many.
Wood's thin-plate *regression* spline truncates: eigendecompose `E` (the kernel between data points), keep the `k` eigenvectors whose eigenvalues are largest in absolute value, and restrict `delta` to their span.
This is the best rank-`k` approximation in a well-defined sense, and it is what mgcv does.

With `delta = U_k delta_k`, the constraint becomes `T' U_k delta_k = 0`: three linear constraints on `k` numbers.
Write `delta_k = Z gamma`, where the columns of `Z` are an orthonormal basis of the null space of `(U_k' T)'`.
Then `gamma` has `k - 3` free entries, and with the three polynomial coefficients the term has `k` coefficients in total, which is the same thing mgcv's `k` counts.

The penalty in terms of `gamma` is exact, not approximate.
`U_k' E U_k = D_k` because the columns of `U_k` are eigenvectors, so

    J = delta' E delta = gamma' Z' D_k Z gamma.

`E` is conditionally positive definite: `delta' E delta > 0` for every nonzero `delta` with `T' delta = 0`.
Every `delta = U_k Z gamma` satisfies that constraint by construction, so `Z' D_k Z` is positive definite even though `D_k` itself mixes signs.
That is a property worth a unit test (section 9).

```rust
use crate::types::DataSet;
use ndarray::{s, Array2};

/// Isotropic thin-plate regression spline in two coordinates (mgcv
/// `bs = "tp"`, second-order penalty).
///
/// One smoothing parameter and a rotation-invariant bending-energy penalty,
/// so the surface does not depend on how the coordinate axes are oriented.
/// Coordinates must share units (a planar projection such as UTM or an
/// equal-area projection); longitude and latitude in degrees are not
/// detected or corrected. Outside the convex hull of the data the surface
/// continues along its linear part.
#[derive(Debug, Clone)]
#[cfg_attr(feature = "serde", derive(serde::Serialize, serde::Deserialize))]
pub struct ThinPlate2D {
    pub col_name_1: String,
    pub col_name_2: String,
    /// Basis dimension, counting the three linear null-space functions
    /// (mgcv's `k`). Default 30.
    pub k: usize,
    /// Cap on the number of knots the kernel is built over (mgcv's
    /// `max.knots`). Default 2000.
    pub max_knots: usize,
    /// Knot coordinates: the unique training locations, subsampled to
    /// `max_knots`. **Leave empty when building a formula.** Resolved at fit
    /// time and stored, like `CrSpline1D::knots`.
    #[cfg_attr(feature = "serde", serde(default))]
    pub knots: Vec<(f64, f64)>,
    /// `U_k Z`, row-major, `knots.len()` x `(k - 3)`. Resolved at fit time.
    #[cfg_attr(feature = "serde", serde(default))]
    pub transform: Vec<f64>,
    /// `Z' D_k Z` after rescaling, row-major, `(k - 3)` x `(k - 3)`.
    /// Resolved at fit time.
    #[cfg_attr(feature = "serde", serde(default))]
    pub penalty: Vec<f64>,
}
```

The matrices are stored as flat `Vec<f64>` rather than `Array2<f64>`.
`ndarray/serde` is available under `serialization`, but its wire format (`{"v":1,"dim":[..],"data":[..]}`) would be the first ndarray-shaped value inside the term schema.
Flat vectors keep the term's JSON plain, and the shapes follow from `knots.len()` and `k`.

The penalty order `m` is fixed at 2 (the only order whose kernel is `r^2 ln r` in two dimensions) and has no field.
`0005`'s SMOOTH-2 sketch named the type `ThinPlate2D` and the file `tp.rs`; this guide keeps both names.

### 4a. The kernel

**`src/splines/tp.rs`**

```rust
//! Thin-plate regression spline in two dimensions (Wood 2003; mgcv `bs = "tp"`).
//!
//! The kernel is `eta(r) = r^2 ln(r) / (8 pi)`, the null space is `{1, x, y}`,
//! and the basis is the eigen-truncation of the kernel matrix between knots,
//! constrained so the kernel part is orthogonal to the null space.

use crate::error::GamlssError;
use crate::linalg::symmetric_eigh;
use ndarray::{concatenate, s, Array1, Array2, Axis};
use rand::rngs::StdRng;
use rand::SeedableRng;

/// Null-space dimension of the second-order thin-plate penalty in 2D.
pub(crate) const TP_NULL_DIM: usize = 3;

/// Thin-plate kernel for d = 2, m = 2: `r^2 ln(r) / (8 pi)`, with eta(0) = 0.
/// The constant matches mgcv; it only rescales lambda.
pub(crate) fn tp_kernel(r: f64) -> f64 {
    if r <= 0.0 {
        0.0
    } else {
        r * r * r.ln() / (8.0 * std::f64::consts::PI)
    }
}

fn distance(a: (f64, f64), b: (f64, f64)) -> f64 {
    ((a.0 - b.0).powi(2) + (a.1 - b.1).powi(2)).sqrt()
}
```

`r^2 ln r` tends to 0 as `r` tends to 0, so the explicit branch is a definition, not a guard.

### 4b. Knot selection

Two rules, both from mgcv.
Duplicate locations are collapsed first, because two identical knots make two identical rows of `E` and the decomposition degenerate (mgcv's `uniquecombs`).
Above `max_knots`, a fixed-seed random subsample is taken (Q-GEO-3, settled the way `0009` leaned).

**`src/splines/tp.rs`** (continued)

```rust
/// Fixed seed for the knot subsample, so the same data always yields the same
/// basis. The stored knots make saved models immune to any change in `rand`'s
/// sampling algorithm; only a refit would see a different subsample.
const KNOT_SEED: u64 = 1;

/// Unique `(x1, x2)` locations, sorted, then subsampled to `max_knots` with a
/// fixed seed when there are more. Sorting first makes the result independent
/// of row order.
pub(crate) fn select_tp_knots(x1: &Array1<f64>, x2: &Array1<f64>, max_knots: usize) -> Vec<(f64, f64)> {
    let mut unique: Vec<(f64, f64)> = x1.iter().copied().zip(x2.iter().copied()).collect();
    unique.sort_by(|a, b| a.0.total_cmp(&b.0).then(a.1.total_cmp(&b.1)));
    unique.dedup();
    if unique.len() <= max_knots {
        return unique;
    }
    let mut rng = StdRng::seed_from_u64(KNOT_SEED);
    let mut chosen = rand::seq::index::sample(&mut rng, unique.len(), max_knots).into_vec();
    chosen.sort_unstable();
    chosen.into_iter().map(|i| unique[i]).collect()
}
```

`rand::seq::index::sample(rng, length, amount)` exists in the `rand 0.10` the crate already depends on (`rand-0.10.3/src/seq/index.rs:240`).
`StdRng` and `SeedableRng` are the same imports `splines::test_support::is_psd` uses.

### 4c. Eigen-truncation and the constraint

This is the heart of GEO-2.
Both decompositions go through `linalg::symmetric_eigh` (`src/linalg.rs:81` on openblas, `:333` on pure-rust), which returns `(eigenvalues ascending, eigenvectors as columns)` on both backends.

**`src/splines/tp.rs`** (continued)

```rust
/// Kernel matrix between knots: `E[i, j] = eta(|knot_i - knot_j|)`.
fn kernel_between_knots(knots: &[(f64, f64)]) -> Array2<f64> {
    let n = knots.len();
    Array2::from_shape_fn((n, n), |(i, j)| tp_kernel(distance(knots[i], knots[j])))
}

/// Null-space polynomial at each knot: `T[i, ..] = [1, x1_i, x2_i]`.
fn polynomial_at_knots(knots: &[(f64, f64)]) -> Array2<f64> {
    Array2::from_shape_fn((knots.len(), TP_NULL_DIM), |(i, c)| match c {
        0 => 1.0,
        1 => knots[i].0,
        _ => knots[i].1,
    })
}

/// Truncate the kernel to its `k` largest-magnitude eigenvectors and absorb the
/// constraint `T' U_k delta_k = 0`. Returns `(transform, penalty)`:
/// `transform = U_k Z` (`n_k x (k-3)`) maps the kernel row to the wiggly
/// coefficients, and `penalty = Z' D_k Z` (`(k-3) x (k-3)`) is their exact
/// bending energy.
pub(crate) fn tp_reparameterize(
    knots: &[(f64, f64)],
    k: usize,
    label: &str,
) -> Result<(Array2<f64>, Array2<f64>), GamlssError> {
    let n_k = knots.len();

    // 1. Eigendecompose E and keep the k eigenvalues largest in absolute value.
    //    E is indefinite, so "largest" means magnitude, not the top of the
    //    ascending list.
    let (eigenvalues, eigenvectors) = symmetric_eigh(&kernel_between_knots(knots))?;
    let mut by_magnitude: Vec<usize> = (0..n_k).collect();
    by_magnitude.sort_by(|&a, &b| eigenvalues[b].abs().total_cmp(&eigenvalues[a].abs()));
    let kept = &by_magnitude[..k];
    let u_k = Array2::from_shape_fn((n_k, k), |(row, col)| eigenvectors[[row, kept[col]]]);
    let d_k = Array1::from_iter(kept.iter().map(|&i| eigenvalues[i]));

    // 2. The constraint T' U_k delta_k = 0 is three equations on k unknowns.
    //    With A = U_k' T (k x 3), its solution space is null(A'). A A' is k x k,
    //    PSD, rank 3; its eigenvectors for the k-3 smallest eigenvalues are an
    //    orthonormal basis of null(A'). This replaces the QR that mgcv uses, and
    //    glissando has no QR on either backend.
    let a = u_k.t().dot(&polynomial_at_knots(knots));
    let (constraint_values, constraint_vectors) = symmetric_eigh(&a.dot(&a.t()))?;
    let largest = constraint_values[k - 1];
    if constraint_values[k - TP_NULL_DIM] <= 1e-10 * largest {
        return Err(GamlssError::Input(format!(
            "thin-plate smooth {label}: the coordinates are collinear, so a 2D surface is not identified"
        )));
    }
    let z = constraint_vectors.slice(s![.., ..k - TP_NULL_DIM]).to_owned();

    // 3. The stored pieces.
    let transform = u_k.dot(&z);
    let penalty = z.t().dot(&Array2::from_diag(&d_k)).dot(&z);
    let penalty = (&penalty + &penalty.t()) * 0.5; // exact in theory; symmetrize the rounding
    Ok((transform, penalty))
}
```

The collinearity check reads the three largest eigenvalues of `A A'`, which are the squared singular values of `A`.
If the third one is effectively zero, `T` has rank below 3 at the knots: all the points sit on one line, and the `y` direction (or some rotation of it) is unidentified.

### 4d. Basis evaluation

**`src/splines/tp.rs`** (continued)

```rust
/// Thin-plate basis at the rows of `(x1, x2)`: the kernel to every stored knot
/// times the stored transform, then the polynomial columns. The constant column
/// is left out when an Intercept shares the parameter.
pub(crate) fn tp_basis_matrix(
    x1: &Array1<f64>,
    x2: &Array1<f64>,
    knots: &[(f64, f64)],
    transform: &Array2<f64>,
    include_constant: bool,
) -> Array2<f64> {
    let n = x1.len();
    let kernel = Array2::from_shape_fn((n, knots.len()), |(i, j)| {
        tp_kernel(distance((x1[i], x2[i]), knots[j]))
    });
    let wiggly = kernel.dot(transform);
    let polynomial = if include_constant {
        Array2::from_shape_fn((n, 3), |(i, c)| [1.0, x1[i], x2[i]][c])
    } else {
        Array2::from_shape_fn((n, 2), |(i, c)| [x1[i], x2[i]][c])
    };
    concatenate(Axis(1), &[wiggly.view(), polynomial.view()])
        .expect("wiggly and polynomial blocks share the row count")
}
```

At prediction time the kernel matrix is `n x n_k`, so at the knot cap a 100,000-row prediction builds a 1.6 GB intermediate.
Chunk the rows if that becomes a problem; it is not one at the scales the tests and parity scenarios use, so this guide does not chunk.

### 4e. Penalty scaling

The kernel grows like `r^2 ln r`, so coordinates in meters (UTM values near 1e5 to 1e6) produce penalty entries around 1e11 and up.
The smoothing parameter would then need `log lambda` near -25, close to the optimizer's clamp at `LOG_LAMBDA_CLAMP = 30` (`src/fitting/solver.rs:29`).
mgcv avoids this with `scale.penalty = TRUE` in `smoothCon`: it rescales each penalty so its norm matches the squared norm of the basis.
GEO-2 does the same, once, at resolve time, and stores the rescaled penalty.

**`src/splines/tp.rs`** (continued)

```rust
/// Rescale a penalty to the scale of its basis, as mgcv's `smoothCon` does with
/// `scale.penalty = TRUE`: multiply by `||X||_inf^2 / ||S||_1`. Only the meaning
/// of lambda changes; the fitted surface does not.
pub(crate) fn scale_penalty_to_basis(penalty: &Array2<f64>, basis: &Array2<f64>) -> Array2<f64> {
    let basis_inf = basis
        .rows()
        .into_iter()
        .map(|row| row.iter().map(|v| v.abs()).sum::<f64>())
        .fold(0.0, f64::max);
    let penalty_one = penalty
        .columns()
        .into_iter()
        .map(|col| col.iter().map(|v| v.abs()).sum::<f64>())
        .fold(0.0, f64::max);
    if penalty_one == 0.0 {
        return penalty.clone();
    }
    penalty * (basis_inf * basis_inf / penalty_one)
}
```

This is the one place GEO-2 goes beyond `0009`.
The scale-invariance test in section 9 is what fails without it.

### 5c. `resolve`: everything expensive, once

The guard is `knots.is_empty()`, the same shape as `CrSpline1D::resolve`.
Once the knots are stored, `resolve` returns the term unchanged, which is what keeps prediction from ever decomposing anything.

```rust
    fn resolve(&self, data: &DataSet) -> Result<Smooth, GamlssError> {
        if !self.knots.is_empty() {
            return Ok(Smooth::ThinPlate2D(self.clone()));
        }
        let label = format!("s({}, {})", self.col_name_1, self.col_name_2);
        let x1 = column(data, &self.col_name_1)?;
        let x2 = column(data, &self.col_name_2)?;
        let knots = select_tp_knots(x1, x2, self.max_knots);
        if self.k <= TP_NULL_DIM {
            return Err(GamlssError::Input(format!(
                "thin-plate smooth {label}: k = {} must exceed the null-space dimension 3",
                self.k
            )));
        }
        if knots.len() < self.k {
            return Err(GamlssError::Input(format!(
                "thin-plate smooth {label}: {} unique locations, fewer than k = {}",
                knots.len(),
                self.k
            )));
        }
        let (transform, penalty) = tp_reparameterize(&knots, self.k, &label)?;
        let training_basis = tp_basis_matrix(x1, x2, &knots, &transform, true);
        let penalty = scale_penalty_to_basis(&penalty, &training_basis);
        Ok(Smooth::ThinPlate2D(ThinPlate2D {
            knots,
            transform: transform.iter().copied().collect(),
            penalty: penalty.iter().copied().collect(),
            ..self.clone()
        }))
    }
```

`Array2::iter` walks in logical row-major order regardless of memory layout, so `iter().copied().collect()` is the flattening that `from_shape_vec` in `assemble` inverts.

### 5d. `assemble`: evaluate, never decompose

```rust
        _n_obs: usize,
        centered: bool,
    ) -> Result<(Array2<f64>, Vec<Array2<f64>>), GamlssError> {
        if self.knots.is_empty() {
            return Err(GamlssError::Internal(format!(
                "ThinPlate2D state for '{}, {}' is unresolved; \
                 call resolve_terms before assemble_model_matrices",
                self.col_name_1, self.col_name_2
            )));
        }
        let wiggly = self.k - TP_NULL_DIM;
        let inconsistent = |_| {
            GamlssError::Input(format!(
                "stored thin-plate state for '{}, {}' does not match k = {}",
                self.col_name_1, self.col_name_2, self.k
            ))
        };
        let transform = Array2::from_shape_vec((self.knots.len(), wiggly), self.transform.clone())
            .map_err(inconsistent)?;
        let wiggly_penalty =
            Array2::from_shape_vec((wiggly, wiggly), self.penalty.clone()).map_err(inconsistent)?;

        let x1 = column(data, &self.col_name_1)?;
        let x2 = column(data, &self.col_name_2)?;
        // With an Intercept on the parameter, drop the constant polynomial column
        // instead of a sum-to-zero transform: the constant is the only direction
        // the two share.
        let basis = tp_basis_matrix(x1, x2, &self.knots, &transform, !centered);

        let n_columns = basis.ncols();
        let mut full_penalty = Array2::<f64>::zeros((n_columns, n_columns));
        full_penalty.slice_mut(s![..wiggly, ..wiggly]).assign(&wiggly_penalty);
        Ok((basis, vec![full_penalty]))
    }
}
```

The `Input` error (rather than `Internal`) is deliberate: the stored state arrives from JSON, which a person can edit.

## 8. glissando vs. mgcv

| | glissando | mgcv `s(x, y, bs = "tp")` |
|---|---|---|
| Kernel | `r^2 ln r / (8 pi)` | same (`d = 2`, `m = 2`) |
| `k` | 30, counting the 3 null-space functions | same |
| Knot cap | `max_knots = 2000` | `max.knots = 2000` (via `xt`) |
| Knot subsample | fixed-seed `StdRng`, after sorting unique locations | its own seeded draw |
| Eigen-truncation | full `symmetric_eigh`, then select | Lanczos iteration for the leading `k` only |
| Constraint `T' delta = 0` | null basis from `symmetric_eigh(A A')` | QR |
| Identifiability with intercept | drop the constant polynomial column | column-mean centering, absorbed by QR |
| Penalty scaling | `||X||_inf^2 / ||S||_1` | same (`scale.penalty = TRUE`) |
| Order `m` | fixed at 2 | selectable |

Both identifiability choices give the same function space once the intercept is included, and the penalty does not touch the constant, so fitted values and EDF are comparable and coefficients are not.
Eigenvectors are defined only up to sign (and up to rotation within repeated eigenvalues), which is a second reason coefficients never match.
The subsamples differ above the cap, so GEO-3 keeps `n` below it.

mgcv's Lanczos approach is faster at large `n_k` because it computes only `k` eigenvectors.
glissando's full decomposition is simpler and reuses the existing backend; at the cap it costs seconds natively.
If that ever matters, a Lanczos path belongs in `linalg.rs` behind the same contract.

```rust
fn bump(x: f64, y: f64) -> f64 {
    (-((x - 0.5).powi(2) + (y - 0.5).powi(2)) / 0.05).exp()
}

/// `n` points uniform on the unit square, y = bump + N(0, 0.1^2).
fn bump_data(seed: u64, n: usize) -> (Vec<f64>, Vec<f64>, Array1<f64>) {
    let mut rng = Generator::new(seed);

        .iter()
        .zip(&x2)

}
```

## 11. Decisions and gotchas

### Prediction must never rebuild the basis

The `0005` sketch rebuilt the kernel from whatever data it was given.
At predict time that is a different basis, and the coefficients mean nothing in it.
Everything data-dependent (knots, transform, penalty) is resolved once in `ThinPlate2D::resolve` and stored, the same contract as `CrSpline1D::knots` and `PSpline1D::range`.

### "Largest eigenvalues" means largest in magnitude

`E` is indefinite and `symmetric_eigh` returns eigenvalues ascending.
Taking the last `k` columns keeps the largest positive ones and drops large negative ones, which is a different and worse basis.
Sort by absolute value, as `tp_reparameterize` does.

### The constraint needs no QR

`glissando` has no QR or SVD on either backend.
The null basis of the `3 x k` constraint comes from the eigenvectors of the `k x k` matrix `A A'` for its `k - 3` smallest eigenvalues.
It is orthonormal for free, and the three largest eigenvalues double as the collinearity check.

### Duplicate locations are collapsed before anything else

Repeated coordinates (several observations at one site) are normal in spatial data.
Two identical knots make `E` singular; deduplication runs first, and the knot count compared against `k` is the unique count.

### The subsample is fixed-seed (Q-GEO-3)

Settled the way `0009` leaned: mgcv-style random sampling with a constant seed, applied after sorting so row order does not matter.
Revisable: a space-filling rule would spread knots more evenly in clustered data.
Changing the rule changes refits, never saved models, because the knots are stored.

### Penalty scaling is required, not cosmetic

Without it, coordinates in meters push the optimal `log lambda` against the clamp at 30, and the fit silently over- or under-smooths.
The unit-invariance test is the guard.
It is also the one addition beyond `0009`'s design; record it in `0009` when this lands.

### Coordinates are taken as given

No rescaling, no projection.
Longitude and latitude in degrees are not detected: a degree of longitude shrinks with latitude, so an isotropic penalty in degrees is anisotropic on the ground.
The doc comment on the variant says so; the cookbook should too.

### Extrapolation is linear

Outside the convex hull the kernel part flattens relative to the polynomial part and the surface continues along its plane.
This is documented behavior, not guarded.

### `max_knots` does not survive a string round trip

`formula_repr` renders `k` but not `max_knots`, because mgcv's string spelling (`xt = list(max.knots = ...)`) has no counterpart in glissando's grammar.
A fitted model is unaffected, because its knots are stored.

### The eigendecomposition is the cost center

At 2000 knots the kernel matrix is 32 MB and the full decomposition takes seconds on openblas.
On `pure-rust`, and especially in WASM, it is slower; the WASM docs should suggest `max_knots(500)` or so for interactive use.
The openblas path falls back to Jacobi only if `*syev` fails (`src/linalg.rs:81-90`); Jacobi at 2000 x 2000 is very slow, so a fallback there will look like a hang.
