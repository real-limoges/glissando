# GEO-1 Implementation Guide: Markov Random Field Smooth

This is a step-by-step walkthrough of GEO-1 from decision `0009`: an areal smooth that shrinks each region toward its neighbors rather than toward zero.
Today glissando's only areal tool is `re(region)`, a ridge-shrunk intercept per region.
`re` treats regions as exchangeable, so two adjacent counties borrow no more strength from each other than two counties at opposite ends of the map.
A region with no observations cannot be predicted at all; it is an error (`src/fitting/assembler.rs:518`).

GEO-1 adds `Smooth::Mrf`, the Gaussian Markov random field that mgcv spells `s(region, bs = "mrf", xt = list(nb = nb))`.
It has one coefficient per region, like `re`, but its penalty is the graph Laplacian of the neighbor structure, so what gets penalized is the difference between neighbors.
Because the neighbor graph, not the data, defines the regions, a region with no observations still gets a coefficient, and the penalty sets it to the average of its neighbors.
The GAMLSS payoff is that this works on any parameter: `sigma ~ mrf(region)` gives a spatially smooth scale surface, which mgcv offers only inside its `*lss` families.

**Done criterion**: a Gaussian or Poisson fit with `mu ~ 1 + mrf(region)` on a lattice graph converges.
A region with few observations is pulled toward its neighbors, and a region with none predicts exactly the mean of its neighbors on the link scale.
The term survives a JSON round trip and is buildable from Rust, Python and JSON.
A formula string `s(region, bs="mrf")` fails with an error that names those three paths.

**Scope**: one new spline module, one new smooth type implementing `SmoothBasis`, two parser arms, and tests.
No change to the assembler, the solver, the families, or the fitting loop.

    src/terms.rs                  <- Smooth::Mrf(Mrf) variant, one arm in Smooth::basis(), Smooth::mrf constructor, py_parse "mrf" arm
    src/terms/smooth.rs           <- declare the new module, re-export Mrf

## 1. Layout

GEO-1 adds a smooth; it does not add a layer.
It follows the smooth contract from the `SmoothBasis` guide: a struct and its trait impl in `terms/smooth/`, its math in `splines/`, one variant and one dispatch arm on `Smooth`.

    Mrf { col_name, neighbors, levels: [] }            built by the user (Rust, Python, JSON)
       |
       v  Mrf::resolve (fit time, once; a no-op once levels are set)
    Mrf { col_name, neighbors: normalized, levels: sorted keys }
       |                                                 stored on FittedParameter::terms
       v  Mrf::assemble (fit AND predict time)
    indicator basis  n x R      graph Laplacian  R x R
       |                          |
       v  apply_sum_to_zero when an Intercept shares the parameter
    B Z  n x (R-1)              Z' L Z  (R-1) x (R-1)
       |
       v
    the existing PWLS solver and smoothing-parameter optimizer, unchanged

The pure math lives in `splines/mrf.rs` and knows nothing about `Term`, `DataSet`, or fitting.
`terms/smooth/mrf.rs` is the only place that touches data.

## 2. Why a Laplacian penalty and not a better random effect

A random effect penalizes `sum(beta_r^2)`: every region is shrunk toward zero, which with an intercept means toward the global mean.
An MRF penalizes `sum over neighbor pairs (beta_i - beta_j)^2`.
That quadratic form is `beta' L beta` with `L = D - A`, where `A` is the adjacency matrix and `D` the diagonal of neighbor counts.

Three consequences follow, and each one shapes the code.

- **Shrinkage goes toward neighbors.**
  A sparsely observed region is pulled toward the regions around it, which is the point of the model.
- **The null space is the per-component constants.**
  `L 1 = 0` for every connected component's indicator vector, so a connected graph has a one-dimensional null space (the overall level).
  Centering against an intercept removes exactly that direction.
  This is why `Mrf::null_dim` has to count connected components.
- **Empty regions are identified by the penalty alone.**
  An unobserved region's coefficient appears only in the penalty terms with its neighbors.
  Minimizing `sum_j (beta_r - beta_j)^2` over `beta_r` gives the neighbor average, so the prediction for an empty region is exactly the mean of its neighbors on the link scale.
  That is an exact, testable property (section 9).

The levels come from the graph's keys, not from the training data.
This deliberately breaks with the `RandomEffect` contract, where the data defines the levels.
For an MRF the graph is the model; the data only informs it.

```rust
//! graph math is in `crate::splines::mrf`; this file owns the term's state and
//! its `SmoothBasis` behavior.

    validate_graph,

/// Gaussian Markov random field over areal regions (mgcv `bs = "mrf"`).
///
/// One coefficient per region in the neighbor graph, penalized by the graph
/// Laplacian, so the penalty is the sum over neighbor pairs of squared
/// coefficient differences. A region with no observations still gets a
/// coefficient; the penalty sets it to the average of its neighbors.
#[derive(Debug, Clone)]
#[cfg_attr(feature = "serde", derive(serde::Serialize, serde::Deserialize))]
pub struct Mrf {
    pub col_name: String,
    /// Region code to neighboring region codes. Codes are numeric, because
    /// `DataSet` columns are f64; they are stored as strings rendered the way
    /// `f64::to_string` renders them ("3", not "3.0"). Stored on the term, so
    /// it serializes with the model and prediction sees the same graph.
    pub neighbors: IndexMap<String, Vec<String>>,
    /// Region codes in coefficient order, sorted numerically. **Leave empty
    /// when building a formula.** Resolved from the graph's keys at fit time
    /// and stored here, so prediction maps regions to the same columns.
    #[cfg_attr(feature = "serde", serde(default))]
    pub levels: Vec<String>,
}
```

### 4a. Key normalization

The data side keys a region by `val.to_string()` on an `f64` (that is what the shared `sorted_levels` helper does, and what `RandomEffect::assemble` does; both moved there from `assembler.rs:237` and `:515` in the `SmoothBasis` refactor).
`3.0_f64.to_string()` is `"3"`.
A user who writes the graph with `"3.0"`, or a Python caller whose dict keys are ints, must land on the same string, so every key and neighbor is parsed as a number and re-rendered.

**`src/splines/mrf.rs`**

```rust
//! Gaussian Markov random field smooth over areal regions (mgcv `bs = "mrf"`).
//!
//! The graph is a map from region code to neighboring region codes. The penalty
//! is the graph Laplacian `L = D - A`, so `beta' L beta` is the sum over
//! neighbor pairs of `(beta_i - beta_j)^2`.

use crate::error::GamlssError;
use indexmap::IndexMap;
use ndarray::Array2;
use std::collections::HashMap;

/// Render a region code the way the data side does: parse it as f64, then
/// `to_string`, so "3", "3.0" and " 3 " all become "3".
pub(crate) fn normalize_region_key(raw: &str, col_name: &str) -> Result<String, GamlssError> {
    let value: f64 = raw.trim().parse().map_err(|_| {
        GamlssError::Input(format!(
            "mrf column '{col_name}': region '{raw}' is not a numeric code \
             (DataSet columns are f64, so regions must be numbered)"
        ))
    })?;
    if !value.is_finite() {
        return Err(GamlssError::Input(format!(
            "mrf column '{col_name}': region '{raw}' is not finite"
        )));
    }
    Ok(value.to_string())
}

/// Normalize every key and neighbor. Two keys that normalize to the same code
/// ("3" and "3.0") are an error rather than a silent merge.
pub(crate) fn normalize_graph(
    neighbors: &IndexMap<String, Vec<String>>,
    col_name: &str,
) -> Result<IndexMap<String, Vec<String>>, GamlssError> {
    let mut normalized = IndexMap::with_capacity(neighbors.len());
    for (raw_key, raw_neighbors) in neighbors {
        let key = normalize_region_key(raw_key, col_name)?;
        let list = raw_neighbors
            .iter()
            .map(|n| normalize_region_key(n, col_name))
            .collect::<Result<Vec<_>, _>>()?;
        if normalized.insert(key.clone(), list).is_some() {
            return Err(GamlssError::Input(format!(
                "mrf column '{col_name}': region '{key}' appears twice in the neighbor graph"
            )));
        }
    }
    Ok(normalized)
}
```

### 4b. Validation

Validation runs once, at resolve time, on the normalized graph.
Each rule exists because breaking it produces a wrong fit rather than a crash.

**`src/splines/mrf.rs`** (continued)

```rust
/// Check the graph is a valid MRF neighbor structure: non-empty, symmetric, no
/// self-loops, no duplicate neighbors, every neighbor is itself a region, and
/// no region is isolated.
pub(crate) fn validate_graph(
    neighbors: &IndexMap<String, Vec<String>>,
    col_name: &str,
) -> Result<(), GamlssError> {
    let fail = |msg: String| Err(GamlssError::Input(format!("mrf column '{col_name}': {msg}")));
    if neighbors.len() < 2 {
        return fail("the neighbor graph needs at least two regions".to_string());
    }
    for (region, list) in neighbors {
        if list.is_empty() {
            return fail(format!(
                "region '{region}' has no neighbors; link it to its nearest region, \
                 or model it with a separate re({col_name}) term"
            ));
        }
        for (position, neighbor) in list.iter().enumerate() {
            if neighbor == region {
                return fail(format!("region '{region}' lists itself as a neighbor"));
            }
            if list[..position].contains(neighbor) {
                return fail(format!("region '{region}' lists neighbor '{neighbor}' twice"));
            }
            match neighbors.get(neighbor) {
                None => {
                    return fail(format!(
                        "region '{region}' lists neighbor '{neighbor}', which is not a region in the graph"
                    ))
                }
                Some(back) if !back.contains(region) => {
                    return fail(format!(
                        "adjacency is not symmetric: '{region}' lists '{neighbor}' but not the reverse"
                    ))
                }
                Some(_) => {}
            }
        }
    }
    Ok(())
}
```

The isolated-region rule is Q-GEO-1 settled the way `0009` leaned: reject, with a message that names both fixes.
An isolated region adds an unpenalized direction that sum-to-zero centering does not remove, and the collapse-warning machinery assumes `null_dim` is known per term.
Revisable: if a real use case needs islands, the alternative is to accept them and count one extra null dimension per component, which `connected_components` below already supports.

### 4c. Levels and connected components

**`src/splines/mrf.rs`** (continued)

```rust
/// Region codes in coefficient order: the graph's keys, sorted numerically so
/// "10" comes after "2" and the layout never depends on insertion order.
pub(crate) fn sorted_region_levels(neighbors: &IndexMap<String, Vec<String>>) -> Vec<String> {
    let mut codes: Vec<f64> = neighbors
        .keys()
        .map(|k| k.parse::<f64>().expect("keys are normalized before sorting"))
        .collect();
    codes.sort_by(|a, b| a.partial_cmp(b).unwrap_or(std::cmp::Ordering::Equal));
    codes.into_iter().map(|c| c.to_string()).collect()
}

/// Connected-component label for each region in `levels` order, numbered from 0.
pub(crate) fn component_labels(
    levels: &[String],
    neighbors: &IndexMap<String, Vec<String>>,
) -> Vec<usize> {
    let index: HashMap<&str, usize> = levels
        .iter()
        .enumerate()
        .map(|(i, l)| (l.as_str(), i))
        .collect();
    let mut labels = vec![usize::MAX; levels.len()];
    let mut next_label = 0;
    for start in 0..levels.len() {
        if labels[start] != usize::MAX {
            continue;
        }
        let mut stack = vec![start];
        labels[start] = next_label;
        while let Some(i) = stack.pop() {
            for neighbor in &neighbors[levels[i].as_str()] {
                let j = index[neighbor.as_str()];
                if labels[j] == usize::MAX {
                    labels[j] = next_label;
                    stack.push(j);
                }
            }
        }
        next_label += 1;
    }
    labels
}

/// Number of connected components: the dimension of the Laplacian's null space.
pub(crate) fn connected_components(
    levels: &[String],
    neighbors: &IndexMap<String, Vec<String>>,
) -> usize {
    component_labels(levels, neighbors)
        .into_iter()
        .max()
        .map_or(0, |m| m + 1)
}
```

`connected_components` recomputes the labels each time it is called.
It runs once per term per assembly on a few hundred or thousand regions, so a cached count would buy nothing and add a field that has to stay in sync.

### 4d. The penalty

**`src/splines/mrf.rs`** (continued)

```rust
/// Graph Laplacian `L = D - A` in `levels` order. Row `i` has the neighbor count
/// on the diagonal and -1 in each neighbor's column, so every row sums to zero
/// and `beta' L beta = sum over edges of (beta_i - beta_j)^2`.
pub(crate) fn mrf_penalty(levels: &[String], neighbors: &IndexMap<String, Vec<String>>) -> Array2<f64> {
    let index: HashMap<&str, usize> = levels
        .iter()
        .enumerate()
        .map(|(i, l)| (l.as_str(), i))
        .collect();
    let r = levels.len();
    let mut penalty = Array2::<f64>::zeros((r, r));
    for (i, region) in levels.iter().enumerate() {
        let list = &neighbors[region.as_str()];
        penalty[[i, i]] = list.len() as f64;
        for neighbor in list {
            penalty[[i, index[neighbor.as_str()]]] = -1.0;
        }
    }
    penalty
}
```

Symmetry of `L` comes for free from the symmetry check in `validate_graph`: if `j` is in `i`'s list then `i` is in `j`'s, so both `[i, j]` and `[j, i]` get the -1.

### 5b. `null_dim`: count the components

```rust
    // Laplacian null space = one constant per connected component. Centering
    // removes the overall constant, which lies in that space.
    fn null_dim(&self, centered: bool) -> usize {
        let components = connected_components(&self.levels, &self.neighbors);
        if centered && self.levels.len() >= 2 {
            components.saturating_sub(1)
        } else {
            components
        }
    }
```

For a connected graph with an intercept this is 0: the centered MRF is full rank, like `RandomEffect`, and the collapse warning (`src/fitting.rs:704-714`) fires only if its EDF drops to 0.5 or below.

### 5c. `resolve`: normalize, validate, resolve levels

`resolve` runs at fit time and again at predict time over the stored term.
It must return the term unchanged once `levels` is set; that guard is what makes prediction reuse the fitted graph instead of recomputing anything.

```rust
    fn resolve(&self, data: &DataSet) -> Result<Smooth, GamlssError> {
        if !self.levels.is_empty() {
            return Ok(Smooth::Mrf(self.clone()));
        }
        let graph = normalize_graph(&self.neighbors, &self.col_name)?;
        validate_graph(&graph, &self.col_name)?;
        let levels = sorted_region_levels(&graph);
        require_observed_components(&levels, &graph, column(data, &self.col_name)?, &self.col_name)?;
        Ok(Smooth::Mrf(Mrf {
            col_name: self.col_name.clone(),
            neighbors: graph,
            levels,
        }))
    }
```

The stored `neighbors` is the normalized graph, so a saved model carries canonical keys and prediction never normalizes again.

### 5d. `assemble`: the indicator basis and the Laplacian

The basis is the same `n x R` indicator matrix `RandomEffect::assemble` builds, with two differences.
The columns come from the graph's levels, which may include regions with no rows at all.
A data value that is not a region in the graph is an error at fit time and at predict time.

```rust
    fn assemble(
        &self,
        data: &DataSet,
        n_obs: usize,
        centered: bool,
    ) -> Result<(Array2<f64>, Vec<Array2<f64>>), GamlssError> {
        if self.levels.is_empty() {
            return Err(GamlssError::Internal(format!(
                "Mrf levels for '{}' are unresolved; call resolve_terms before assemble_model_matrices",
                self.col_name
            )));
        }
        let region = column(data, &self.col_name)?;
        let region_to_column: HashMap<&str, usize> = self
            .levels
            .iter()
            .enumerate()
            .map(|(i, l)| (l.as_str(), i))
            .collect();

        let n_regions = self.levels.len();
        let mut basis = Array2::<f64>::zeros((n_obs, n_regions));
        for (i, value) in region.iter().enumerate() {
            let key = value.to_string();
            match region_to_column.get(key.as_str()) {
                Some(&col) => basis[[i, col]] = 1.0,
                None => {
                    return Err(GamlssError::Input(format!(
                        "mrf column '{}' has region '{key}' that is not in the neighbor graph",
                        self.col_name
                    )))
                }
            }
        }

        let penalty = mrf_penalty(&self.levels, &self.neighbors);
        // The indicator basis is partition-of-unity, so with an Intercept the
        // constant direction has to go. Unlike RandomEffect, Z' L Z is not the
        // identity, so this goes through the shared helper.
        if centered && n_regions >= 2 {
            Ok(apply_sum_to_zero(&basis, &[&penalty], n_regions))
        } else {
            Ok((basis, vec![penalty]))
        }
    }
}
```

`apply_sum_to_zero` returns `B Z` and `Z' L Z` with `Z = sum_to_zero_basis(R)`.
`Z` depends only on `R`, so prediction reapplies the same constraint.

### 5e. The one rule that needs both graph and data

Every connected component must contain at least one observed region.
A component with no observations has a level that neither the data nor the penalty pins down (the penalty only constrains differences within it), so `X'WX + lambda S` is singular in that direction.
With centering the free direction becomes collinear with the intercept instead, which is no better.

```rust
/// Every connected component of an MRF graph must contain at least one region
/// that appears in the training data; otherwise that component's overall level
/// is not identified.
fn require_observed_components(
    levels: &[String],
    neighbors: &IndexMap<String, Vec<String>>,
    region: &Array1<f64>,
    col_name: &str,
) -> Result<(), GamlssError> {
    let observed: HashSet<String> = region.iter().map(|v| v.to_string()).collect();
    let labels = component_labels(levels, neighbors);
    let n_components = labels.iter().max().map_or(0, |m| m + 1);
    for component in 0..n_components {
        let members: Vec<&String> = levels
            .iter()
            .zip(&labels)
            .filter(|(_, &label)| label == component)
            .map(|(level, _)| level)
            .collect();
        if !members.iter().any(|m| observed.contains(m.as_str())) {
            return Err(GamlssError::Input(format!(
                "mrf column '{col_name}': the connected component containing region '{}' \
                 has no observations, so its level is not identified",
                members[0]
            )));
        }
    }
    Ok(())
}
```

It is a private function in `terms/smooth/mrf.rs` rather than part of `splines/mrf.rs`, because it is the one rule that reads data.

## 6. The surfaces: JSON, WASM, Python

**JSON** needs no code.
`Smooth` derives `Serialize`/`Deserialize` with the default external tagging, so the new variant serializes as:

```json
{"Smooth": {"Mrf": {"col_name": "region",
                    "neighbors": {"0": ["1", "3"], "1": ["0", "2", "4"], "2": ["1", "5"]},
                    "levels": []}}}
```

`levels` may be omitted on input (`serde(default)`).
A saved model carries the resolved levels and the normalized graph.

**WASM** delegates to `json`, and nothing in `src/wasm.rs` enumerates smooth variants.
The only WASM task is regenerating `pkg/` (section 12).

**Python** goes through `py_parse::parse_smooth` (`src/terms.rs:614`).
Its `bs` match has one real arm, `"cr"`, and a wildcard at line 652 that builds a P-spline.
That wildcard means `{"bs": "mrf"}` today silently fits a P-spline on the region codes, and so does a typo like `{"bs": "crr"}`, or `{"bs": "re"}`.
GEO-1 adds the `"mrf"` arm and turns the wildcard into an explicit `"ps"` arm plus an error.

## 8. glissando vs. mgcv

mgcv's `smooth.construct.mrf.smooth.spec` builds the same penalty: the neighbor count on the diagonal, -1 per neighbor.
The two differ in three places, none of which changes fitted values.

| | glissando | mgcv |
|---|---|---|
| Graph input | `(region, neighbors)` pairs of numeric codes | `xt = list(nb = nb)`, a named list of index vectors; or `xt = list(polys = ...)` to derive it |
| Identifiability | coefficient sum-to-zero, `B Z` and `Z' L Z` | column-mean centering constraint absorbed by QR |
| Rank | full: one coefficient per region | full by default; `k` below the region count truncates to leading eigenvectors of `L` |

The constraints differ but span the same function space once the intercept is included, and `L 1 = 0` makes the penalty indifferent to the constant.
So coefficients are not comparable across the two, but fitted values and EDF are, which is what GEO-3 compares.
Reduced rank is deferred (`0009`, "Out of scope"); it matters only for graphs with many thousands of regions.
Deriving the graph from polygons is also out of scope; that is a GIS job and belongs upstream of glissando.

The R `gamlss.spatial::gmrf()` term runs a GMRF inside the same RS algorithm glissando uses.
It is the closest precedent for `sigma ~ mrf(region)`.

```rust
// GEO-1: Markov random field smooth over areal regions. These go through the
// public API only: build a lattice graph, fit, predict, and check the
// properties that make an MRF different from a random effect.
#![cfg(not(feature = "python"))]

mod common;

use common::Generator;
use glissando::{distributions::Gaussian, DataSet, Formula, GamlssModel, Smooth, Term};
use ndarray::Array1;
use rand_distr::{Distribution, Normal};

/// Rook-adjacency lattice: region `r * cols + c` neighbors the regions directly
/// above, below, left and right.
fn rook_lattice(rows: usize, cols: usize) -> Vec<(String, Vec<String>)> {
    let code = |r: usize, c: usize| (r * cols + c).to_string();
    let mut graph = Vec::with_capacity(rows * cols);
    for r in 0..rows {
        for c in 0..cols {
            let mut list = Vec::new();
            if r > 0 { list.push(code(r - 1, c)); }
            if r + 1 < rows { list.push(code(r + 1, c)); }
            if c > 0 { list.push(code(r, c - 1)); }
            if c + 1 < cols { list.push(code(r, c + 1)); }
            graph.push((code(r, c), list));
        }
    }
    graph
}

/// `per_region` observations in every region except those in `skip`, with a
/// true region effect that rises down the rows.
fn lattice_data(
    rng: &mut Generator,
    rows: usize,
    cols: usize,
    per_region: usize,
    skip: &[usize],
) -> (Array1<f64>, DataSet) {
    let noise = Normal::new(0.0, 0.3).unwrap();
    let mut region = Vec::new();
    let mut y = Vec::new();
    for code in 0..rows * cols {
        if skip.contains(&code) {
            continue;
        }
        let truth = (code / cols) as f64 * 0.5;
        for _ in 0..per_region {
            region.push(code as f64);
            y.push(truth + noise.sample(&mut rng.rng));
        }
    }
    let mut data = DataSet::new();
    data.insert_column("region", Array1::from_vec(region));
    (Array1::from_vec(y), data)
}

fn mrf_formula(graph: Vec<(String, Vec<String>)>) -> Formula {
    Formula::new()
        .with_terms("mu", vec![Term::Intercept, Term::smooth(Smooth::mrf("region", graph))])
        .with_terms("sigma", vec![Term::Intercept])
}

fn predict_regions(model: &GamlssModel, codes: &[usize]) -> Vec<f64> {
    let mut data = DataSet::new();
    data.insert_column("region", Array1::from_iter(codes.iter().map(|&c| c as f64)));
    model.predict(&data, &Gaussian::new()).unwrap()["mu"].to_vec()
}

/// The defining property: a region with NO observations predicts exactly the
```

## 11. Decisions and gotchas

### Levels come from the graph, not the data

This is the one contract difference from `RandomEffect`, and every other rule follows from it.
The graph defines the coefficient columns; the data only has to be a subset of the graph.
Regions in the graph with no rows are expected, not an edge case.

### Region keys must be normalized before anything compares them

The data side keys rows by `f64::to_string`, which renders `3.0` as `"3"`.
A graph written with `"3.0"`, or built from Python ints, compares unequal unless normalized.
`normalize_graph` runs once in `Mrf::resolve`, and the stored term carries the normalized graph, so nothing downstream normalizes again.

### Isolated regions are rejected (Q-GEO-1)

A region with no neighbors has no penalty and, if empty, no design either.
The error names both fixes: link it to its nearest region, or model it with a separate `re(...)` term.
Revisable without breaking saved models; accepting islands means counting one extra null dimension each, which `connected_components` already does.

### Every component needs an observed region

Disconnected graphs (islands of two or more regions) are allowed, but each component's level is identified only by its own data.
`require_observed_components` checks this in `Mrf::resolve`, because it is the one rule that needs both the graph and the data.

### `resolve` must be a no-op once `levels` is set

The trait makes `resolve` required, so it cannot be forgotten, but the "already resolved" guard inside it can be.
Without the guard, prediction would re-run validation against the prediction data and fail on any graph component the new rows do not touch.
`resolve_is_a_no_op_once_levels_are_set` is the test for exactly that.

### `Z' L Z` is not the identity

`RandomEffect::assemble` hard-codes the centered penalty as `eye(n_groups - 1)` because `Z' I Z = I`.
Copying that method for the MRF would silently turn it back into a random effect.
`Mrf::assemble` goes through `apply_sum_to_zero`.

### `term_name` is deliberately not `s(region)`

Terms are still keyed by their display string (backlog Altitude #6), and `RandomEffect` already renders as `s(region)`.
`Mrf` renders as `s(region, bs="mrf")`, so `re(region) + mrf(region)` (a legitimate BYM-style model: unstructured plus spatial) keeps two distinct keys in `term_blocks` and in model selection.

### `formula_repr` renders a spelling the parser rejects

`s(region, bs="mrf")` is what a printed model should show.
It also means `Mrf` must stay out of the round-trip lists in `parse.rs:402` and `tests/formula_parse.rs:100`, since the graph cannot survive a trip through a string.
If Q-GEO-2 is ever revisited to accept the string with a separately supplied graph, those lists gain the spelling then.

### The Python wildcard was hiding bugs

Before this guide, any unrecognized `bs` in the Python tuple form built a P-spline.
GEO-1 makes the match explicit and the fallback an error.
Mention it in the changelog when this lands.
